# Challenge System

## 职责

Challenge 表示当前地点中可准备、可直接尝试，并具有明确成功与失败后果的短
风险选择。

玩家应能在执行前看到：

- 使用的属性与骰子。
- 当前难度。
- 准备会增加多少。
- 成功可能得到什么。
- 失败会付出什么，但不会被模糊成一句“行动失败”。

## 基础结算

`V5ChallengeResolver` 支持：

- 准备耗时与准备状态。
- 属性、骰点、准备加值和难度公式。
- 成功或失败状态。
- 成功发现物与物品来源。
- 失败健康损失与持续伤势。
- 一次性结算与过期选项拒绝。

## 可选成功事实

`success.additional_facts` 允许挑战成功声明现场发现的具体事实。

Resolver 会为每条事实补入：

- 唯一事实 ID。
- 当前挑战、地点、日期和小时。
- 当前检定事实与发现物事实作为原因。
- `visibility` 和 `source_action`。

数据仍需明确填写 `fact_type`、`source_id`、`target_id`、`summary`，以及必要的
认识状态字段。

北埠旧档房使用 `epistemic_status = document_claim` 表示：

> “那批粮不是霉”是陆槐旧验粮簿中的说法，不是系统已经证明的客观真相。

## 可选挑战纪事

`V5ChallengeChronicleBuilder` 只在 `success.chronicle` 存在时工作。

它验证并引用：

- 抵达当前地点的指定路线事实。
- 当前挑战的准备事实，如果实际发生。
- 成功检定事实。
- 发现物事实。
- 配置要求的额外事实。
- 实际获得的物品。
- 分句级 `claims`。

来源不完整时不会生成纪事。没有配置 Chronicle 的既有挑战保持原行为。

## 边界

Challenge 不负责：

- 替代通用行动规则。
- 在失败后自动重置危险。
- 把文书、传言或人物判断升级为全知事实。
- 创造不存在的抵达路线。
- 处理多年后的返程回响。

旧档房失败会造成手掌割伤并封闭入口；成功会取得陆槐最后一页验粮簿。两个结果
都来自同一检定公式，且都只结算一次。
