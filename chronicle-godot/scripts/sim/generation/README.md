# Generation Contracts

本目录负责把生成结果写成正式模拟可以消费的 fixture 数据。生成顺序不能交换：

1. `SettlementGenerator` 读取场址地形、资源和交通，生成聚落实体、承载力、人口目标、产业、设施、压力、内部道路、资源库存、来源事实和纪事。
2. `SettlementNetworkGenerator` 可以按同一世界种子依次生成多个场址，为各地隔离居民与家庭 ID 命名空间，建立跨聚落双向道路和贸易储备。
3. 聚落生成器把人口目标、聚落实体、职业到设施的绑定以及职业到具体资源库存的绑定写回 `resident_generation` 配置。
4. `ResidentGenerator` 只从被选中的职业池生成居民，并把家庭、住址、工作地、生计、关系、物品和事实写入同一 fixture。
5. `SimSession` 以生成后的 fixture 创建正式 Store；存档保存完整 bootstrap 和生成报告，读取时校验既有结果，不重新抽取。

## Settlement Input

`settlement_generation` 至少包含：

- `definition_path`：地形、规模和产业原型定义。
- `terrain`：地形类型、可居住面积、地形标签和灾害暴露。
- `resources`：资源 ID、标签、丰度和可靠性。
- `traffic`：来路 ID、交通方式、运量、可靠性和风险。

容量由地形基础值、可居住面积、资源支撑、交通运量和有界种子扰动共同计算。人口目标只能在容量以内产生。产业先检查必要资源或交通准入，再依据地形、资源、交通和有界种子分数排序；不能仅凭随机数生成缺少生产条件的产业。

每个被选产业必须产出：

- 一个正式 `Location`；
- 一个可检查现场对象；
- 一对连接公共集地的正式 `travel_route`；
- 至少一个已绑定职业；
- 一条带来源 ID 的产业事实。
- 一项可核对的资源库存绑定；不消耗资源的守望等服务产业可以明确留空。

## Dynamic Resource Stock

自然资源和交通运力会生成 `ResourceStockStore` 记录。每项记录包含来源、容量、当前水位、每小时恢复量、开工线、服务产业和设施引用。居民生产通过统一事务同时写入资源消耗、生产事实和物品；资源不足时整轮生产停止，不创建物品。

`SettlementResourceSystem` 在世界 Tick 中先执行自然恢复，再让生计消耗库存，最后依据实际水位更新设施状态、粮食压力、资源负担和迁离倾向。资源跌破开工线或重新越过开工线时会形成事实、压力记录和聚落纪事。

## Settlement Network

`settlement_network_generation` 提供多个场址、连接和贸易货物规则。生成器仍复用单聚落合同，不复制第二套实体模型。跨聚落道路的端点必须是已生成公共集地，居民生计按 `settlement_id::occupation_id` 绑定当地库存，不能错误消费另一个聚落的同名职业资源。

网络运行时包含场址、道路、日运力、旅行时间、风险、贸易货物、住宅容量和迁移/吸纳等待天数。世界 Tick 会消费各地贸易储备，依据来源富余、目的短缺和道路容量形成货流；连续高压力会让整户居民迁往有容量且压力更低的相邻聚落。

网络居民生成会把最大家庭规模限制在单处住宅容量内，并可为每个聚落生成少量带来源的空置住宅。所有生成住宅都声明所属聚落；空置住宅是正式地点资产，不是吸纳发生时临时伪造的地址。

## Honest Boundary

当前 G3-D 已覆盖三个聚落、两条区域连接、受库存与运力约束的货流、连续短缺后的真实整户迁移，以及受住宅和岗位容量约束的目的地吸纳。它仍从手工配置的场址输入、货物类型、产业原型、设施描述和职业池开始，没有生成区域地形图、任意规模路网、动态住宅建设或企业生命周期，不能把本合同描述成完整世界生成。
