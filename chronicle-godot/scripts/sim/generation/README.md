# Generation Contracts

本目录负责把生成结果写成正式模拟可以消费的 fixture 数据。生成顺序不能交换：

1. `SettlementGenerator` 读取场址地形、资源和交通，生成聚落实体、承载力、人口目标、产业、设施、压力、内部道路、来源事实和纪事。
2. 聚落生成器把人口目标、聚落实体和职业到设施的绑定写回 `resident_generation` 配置。
3. `ResidentGenerator` 只从被选中的职业池生成居民，并把家庭、住址、工作地、生计、关系、物品和事实写入同一 fixture。
4. `SimSession` 以生成后的 fixture 创建正式 Store；存档保存完整 bootstrap 和两层生成报告，读取时校验既有结果，不重新抽取。

## Settlement Input

`settlement_generation` 至少包含：

- `definition_path`：地形、规模和产业原型定义。
- `terrain`：地形类型、可居住面积、地形标签和灾害暴露。
- `resources`：资源 ID、标签、丰度和可靠性。
- `traffic`：来路 ID、交通方式、运量、可靠性和风险。

容量由地形基础值、可居住面积、资源支撑、交通运量和有界种子扰动共同计算。人口目标只能在容量以内产生。产业先检查必要资源或交通准入，再依据地形、资源、交通和有界种子分数排序；不能仅凭随机数生成缺少生产条件的产业。

每个被选产业必须产出：

- 一个正式 `Location`；
- 一个可检查现场对象；
- 一对连接公共集地的正式 `travel_route`；
- 至少一个已绑定职业；
- 一条带来源 ID 的产业事实。

## Honest Boundary

当前 G3-A 生成的是单个已知场址上的聚落结构。场址输入、产业原型、设施描述和职业池仍由数据定义提供。系统尚未生成区域地形图、资源地质、多聚落网络或会枯竭和恢复的资源库存；不能把本合同描述成完整世界生成。
