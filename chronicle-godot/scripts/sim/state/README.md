# State / Need System

## 职责

管理实体的数值、状况和需求压力。

## 管理的数据

生命、健康、精力、理智、饥饿、恐惧、疲劳、年龄、疾病、腐败度、新鲜度、湿度和损坏度。

## 输入

时间推进、行动事务、物品效果、地点环境、地区压力和长期项目。

## 输出

状态变化、需求压力、行为倾向、行动条件、叙事素材和结算素材。

## 不负责什么

不负责直接写 UI 文本，不负责创建实体，不负责生成传闻。

## 与其他系统的关系

Action 读取状态作为候选条件，Transaction 写回状态变化，Narrative Surface 把状态翻译为文本。

## 当前状态

阶段 5.5 步骤 2A 已接入正式运行链：

- `StateStore` 是人物、对象、地区与制度可变状态的唯一真值。
- 每个已注册字段由 StateDef 约束所有者、值类型、范围和允许操作。
- 严格模式拒绝未知字段和非法写入；旧 fixture 暂以兼容模式装载，并按字段汇总迁移警告。
- 兼容只作用于旧数据导入；已注册字段进入运行时后仍严格执行类型、范围、所有者和操作边界。
- `SimSnapshotBuilder` 将 EntityStore 的静态元数据与 StateStore 的可变状态合并为只读投影。

当前 Raw StateDef 只覆盖基础公共字段，旧 fixture 的领域专属字段仍待分批注册。
