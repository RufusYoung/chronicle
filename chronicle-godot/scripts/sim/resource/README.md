# Settlement Resource System

本目录管理生成聚落的长期资源库存。

## ResourceStockStore

每项库存保存：

- `stock_id`、原始资源或交通来源 `source_id`；
- 所属聚落、所在生产地点、服务产业和设施实体；
- `capacity`、`current`、`recovery_per_hour` 与 `operating_floor`；
- 当前 `status`、来源事实、最后一次变化和累计变化次数。

所有消耗、恢复和外部调整都通过 `TransactionResult.resource_changes` 进入统一 Writer。透支或越界会在预检阶段拒绝整笔事务，不能留下已经生产物品但没有消耗资源的半写状态。

## SettlementResourceSystem

每个世界小时按固定顺序执行：

1. 未满库存按自身可靠性恢复；
2. 居民生计读取绑定库存并尝试生产；
3. 实际水位重新计算设施开工状态；
4. 粮食压力、资源负担和迁离倾向写回地区状态；
5. 跌破或重新越过开工线时形成事实、压力记录和聚落纪事。

资源库存是世界真值，地点界面只读取 Snapshot 投影，不维护第二份 UI 数值。

## SettlementNetworkSystem

多聚落网络在上述本地资源循环之后执行三类日常事务：

1. 各地人口消费当地贸易储备；
2. 货物从有自然库存富余的聚落流向储备短缺的相邻聚落；
3. 连续高压力达到阈值后，家庭迁往有容量且压力更低的邻居。

每批贸易同时消耗来源自然库存和来源道路运力，并增加目的地贸易储备。事实保留来源聚落、目的聚落、两端库存、运输库存、数量、价格和日期。系统在同一 Tick 内维护虚拟可用量，防止多批货物超卖同一库存或运力。

迁移会同步修改家庭位置以及每名成员的聚落、当前位置、住址、工作地和生计状态。劳动者抵达后转为失业，旧聚落的同名职业不会继续替其生产。目的地住房与再就业属于后续吸纳合同。
