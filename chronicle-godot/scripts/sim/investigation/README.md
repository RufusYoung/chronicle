# Investigation Direction System

## 职责

调查方向表示玩家已经获得、但尚未决定何时处理的可行动线索。

它需要同时保留：

- 线索从哪些事实和物品产生。
- 当前应在什么地点处理。
- 玩家尚未决定、已经搁置或已经完成。
- 搁置与恢复调查分别发生在什么时间。
- 最终发现指向哪个人物、地点或物件。

调查方向不是任务清单。它不会要求玩家必须完成，也不会因为玩家继续生活就自动
失败。世界时间可以继续推进，线索仍由结构化状态保存。

## 当前实现

- `V5InvestigationLeadStore`：保存调查方向、状态、处置方式和操作履历。
- `V5InvestigationResolver`：结算“立即追查”与“暂时搁置”，统一产生事实、
  人物状态、关系、记忆、物品履历和调查状态变化。
- `V5InvestigationChronicleBuilder`：从调查来源和实际选择生成有证据引用的
  个人纪事分支。
- `TransactionResult.investigation_changes`：让调查变化进入统一事务写回。
- `SimSnapshot.investigation_leads`：把仍开放的调查方向投影到当前地点和界面。

第一条调查方向是“公仓封存记录”：

```text
陈米认出验粮铜牌
→ 确认旧公仓封闭的地方史
→ 打开陈家旧税契调查方向
→ 立即翻查，或先继续生活
→ 从封印抄件找到验粮吏陆槐与北埠旧档房
```

## 状态语义

`status` 表示调查是否仍可处理：

- `open`：仍然有效。
- `resolved`：已经完成，不能重复结算。

`disposition` 表示玩家如何对待这条方向：

- `fresh`：尚未决定。
- `deferred`：已经明确搁置，但仍保持开放。
- `investigated`：已经追查并结案。

搁置不会创建一个新的调查方向，也不会清除原线索。恢复调查时，结算和纪事必须
引用此前的 `defer_fact_id`，因此“先过日子，后来又回来查”是可验证的实际分支，
不是只换一句文本。

## 与其他系统的边界

调查方向不同于：

- `Obligation`：没有必须履行的承诺、债权人或默认违约含义。
- `DeferredConsequence`：不是等待到期自动触发的后果。
- `Rumor`：不只是信息，它能在当前世界状态中生成明确行动。
- `Chronicle`：纪事只记录已发生的选择，不负责推动调查。
- `WorldLog`：日志记录结算，调查仓库保存持续可行动状态。

调查 Resolver 不直接写入 Store。它只产生 `TransactionResult`，再由
`TransactionWorldWriter` 原子写回事实、人物、关系、记忆、物品、调查和纪事。

## 证据要求

调查纪事必须引用：

- 打开调查方向的全部来源事实。
- 关联物品。
- 本次搁置或追查产生的新事实。
- 恢复调查时此前的搁置事实。
- 本次人物记忆。

任何必要来源缺失时，Builder 会拒绝生成条目，避免界面凭空宣称玩家调查过、
搁置过或发现过某件事。
