# 玩家能动性、共享时钟与统一前台

日期：2026-09-03

分支：`codex/player-agency-world-surface`

基线：`992748b`

## 本轮结果

普通现场操作现在会消耗时间，期间人物与世界继续运行；行动结果、同期世界变化和完整记录不再混在同一个列表里。老陈铺子和第七哨站共用一套现场、角色、记录页面。

这改善了无成本点完所有选项、看不出自己影响和界面裁切的问题，但没有完成开放世界生涯，也没有新增文明政治系统。本轮不扩写固定的后续年份剧情。

## 输入如何进入世界

`当前快照 -> 可执行候选及成本 -> 行动事务 -> 推进共享时钟 -> 人物和世界规则 -> 新候选、直接结果与同期变化`

- `SimSession.execute_timed_action` 是正式现场操作的入口。成功后只推进一次候选声明的时长；失败或过期候选不会再次消耗时间、物资或写入日志。
- 原有 `execute_action` 仍是单次事务接口，供低层合同验证和测试注入使用，避免悄悄改变已有模拟脚本的时钟语义。
- 行动卡的时长来自同一份候选数据。两小时的规则覆盖会同时改变显示成本和真实结算，不出现界面写一小时、后台走两小时的情况。
- 第七哨站保留职责事务、日常事务、结算前后状态与世界 Tick 收据。存档载入后仍能区分这些来源。

## 可以复验的差异

### 相同时间的帮助与旁观

使用默认 fixture 种子 516，两条对照都从第 1 天 10:00 到 11:00。

- UI 自动操作帮助分支：发出给陈米食物按钮的信号。口粮消耗、饥饿变化和一小时世界推进依次结算，老陈读取变化后的处境，形成 `merchant_kept_shop_open`。
- 旁观分支：只推进一小时，形成 `merchant_closed_shop_early`。
- 重复调用已经消失的帮助候选，时钟和世界日志均不增加。

这项对照支持“外部输入改变了既有世界规则所读取的条件”。它不能证明所有后续变化都由这次输入造成，也不能证明完整的矮人要塞式涌现已经完成。

### 职责与日常变化分开计算

巡查雾线的直接事务中，边境压力为 -3；随后日常事务中为 +2。界面分别说明直接影响与同期变化，不把净变化简单归功于一个按钮。

## 界面规则

1. 现场页集中展示地点、当前结果、人物与物证摘要、决定依据及行动。危险出现时，风险说明替代重复的试玩目标说明。
2. 角色页完整展示六项属性、成长、印记、装备和随身补给。印记阶段使用中文，不显示内部枚举。
3. 记录页保存完整现场描述、已确认信息、行动历史和本次完整结算。只有记录页使用统一滚动区域，没有互相争抢滚轮的小框。
4. 行动每页四项，页码明确说明总数；所有候选均可访问，翻页没有世界时间成本。当前危险、调查和辨认旧物优先展示，但不删除其他选择。
5. 现场摘要优先显示未处理的实体信息，已阅读的物件与大量环境痕迹保留在记录。摘要的省略会明确标出剩余数量。
6. 决策必要信息不只藏在记录里。姓名与去向直接出现在阅读反馈；敌人的可观察特征、危险公式、不可逆代价留在现场；口粮、装备、伤势和长期印记优先进入结算摘要。

## 验证记录

115 项短回归的逐项最新结果全部通过。这里是初次完整扫描、界面批量复跑与针对性修复复跑的去重汇总，不是宣称第一次批量运行就全绿。机器可读结果保存在同目录 `2026-09-03_player_agency_regression_results.json`，每项注明来源批次。

其中 33 项重建界面测试已全部通过，涵盖生成聚落、组织、资源、地区网络、服役阶段、战斗与完整旧井路径。两个新增测试均通过；统一界面测试和完整路径另用真实渲染器运行，截图与控件边界检查同时通过。旧入口烟测修正后额外连续运行五次，5/5 通过。Godot 编辑器导入与脚本解析未发现错误。

本轮没有重跑三十日生成世界健康测试；不把以前的长跑结果计入本轮的 115 项。

新增验证：

- `v5_player_agency_surface_test.gd`：同时间对照、过期候选、记录保留、统一布局、17 项测试注入行动的分页可达性、职责与日常事务分离。
- `player_action_time_receipt_test.gd`：事务接口与计时接口的边界、规则时长覆盖、存档往返的因果收据；通过测试注入模拟 Tick 失败，确认已生效的行动不会被重复消费。
- `v5_playtest_ux_regression_test.gd`：逐个发出实际存在且可见的按钮信号，走完老陈铺子、旧粮仓、北埠档房、旧井和返回流程；每步检查可见控件边界、正文高度与滚动状态。

实际使用 Godot 4.6.3、Compatibility 渲染器，在 1280×720 下查看了阅读、风险、返回、哨站职责和角色页截图。这是 UI 自动操作与图像检查，不是人工高强度长时间试玩，也不能替代陌生玩家的理解和乐趣测试。

测试中发现并修正的验收问题：

- 旧界面测试假定普通交谈、阅读不花时间；现按真实经过的小时更新预期，同时保留过期候选和状态真值断言。
- 旧测试依赖固定父节点路径、小框高度和滚动条。现验证可见边界、完整正文和记录入口，不把隐藏内容宣称为首屏已显示。
- 旧入口烟测选择器未过滤仍在场景树中、已经排队删除的控件。选择器现在跳过这些控件和不可见区域，并允许行动进入下一阶段或直接给出结算反馈。
- 部分生成网络测试需要超过两分钟。统一运行器正常测试上限为十分钟，三十日健康测试单独使用三十分钟上限；缺失定义的负向测试只放行它明确预期的那一条错误，脚本错误仍算失败。

复验命令，在项目根目录运行：

```powershell
& ./chronicle-godot/tests/run_regression.ps1 -Godot <Godot可执行文件路径> -Render
```

默认不运行 `generated_world_30_day_health_test.gd`；需要它时另加 `-LongRun`。日志与逐项 JSON 结果默认写入临时目录 `chronicle-agency-regression`。

## 尚未完成

- 普通行动是一小时的粗粒度预算，尚非分钟级日常活动模拟。已有同袍、商店、装备与数值合同也不代表整套开放世界玩法完成。
- 世界可独立变化，输入可改变部分条件，但当前可介入渠道仍有限，不能宣称已经消除“哪里亮点哪里”的全部问题。
- 行动事务与世界推进不是整体回滚事务。若后者失败，前者可能已生效；界面提示不要重复执行，本轮没有新增原子回滚。
- 完整文明摩擦仍缺资源所有权、组织预算、利益分配、权限与竞争性目标。现有货流、迁徙和道路事故不能替代这些机制。
- 下一系统阶段保留 G5-C2 产业创生与退场，随后落实 W1 资源权属与预算、W2 跨地区利益冲突、W3 不同人物对同一变化的差异化反应。

理解本轮边界的两个检查问题：同样到 11:00，为何两条对照的商铺事实不同？职责直接降低边境压力 3 点，为何最终状态未必降低 3 点？答案分别在共享状态条件和后续独立结算中，不能仅从一段叙事推断。
