# 后台代理入口与限期世界优先计划

日期：2026-09-05。

## 结果与判断

已建立不依赖屏幕的代码级游玩入口，支持启动、观察、正式候选行动、世界推进与存读档。外部 AI 可以驱动一个持续运行的 Godot 进程，世界不会每次请求重新启动；世界观察模式与角色游玩模式的权限分开。

这项工作改善了测试和后续开发的可观察性，没有直接解决世界单调、UI 信息过载或玩法重复。本轮不增加“完整涌现”与“Steam Demo”完成度，也不把接口或回归数量计算为好玩程度。

用户追加了 Tripothon S1 中国赛区目标，活动计划现以 2026 年 10 月 5 日前交付为约束，内部完整交付定在 10 月 4 日 18:00。H0 本轮完成，下一步 H1 处理连续小世界、运行性能、早期独立包与视觉样例；9 月 24 日前必须形成完整首次体验，9 月 28 日冻结功能。

## 实现范围

- `scripts/agent/agent_game_session.gd` 作为统一协议边界，复用 SimSession、地点 ViewModel、第七哨站 ViewModel 和原生 SaveEnvelope。
- `agent_stdio_runner.gd` 运行在 headless 模式，用有长度前缀的 UTF-8 JSON 处理请求；不监听端口，不需要外部服务。
- `tools/agent_play.py` 是标准库 Python 客户端，可导入，也可作为 JSONL 标准输入输出桥。超时不自动重试，关闭时回收所属进程。
- world 模式能启动已有生成聚落网络，推进自然演算、按页查事实与实物记录，不能控制旅人。play 模式使用正式界面同源的合法候选与可见内容，不能调用全知查询或注入 effects/骰点。
- 请求具备进程身份、单调修订号与有界去重缓存。读过的一次性选项退出候选，陈旧命令不能再次执行。
- 原生存档追加控制模式和显示反馈元数据，保存于独立槽位。读档先在新会话验证成功再替换现有会话；不覆盖 UI 现有存档。
- 第七哨站开局新增可选种子参数向正式会话透传，旧调用参数与默认行为不变；没有改写经济、角色决策或 UI 布局。

接口全文见项目根目录 `texts/specs/AI_GAME_CONTROL_API.md`；活动计划见 `texts/v5/CHRONICLE_WORLD_FIRST_PLAN_v5.1.md`。

## 实际后台运行

以下均不是真实 UI 输入。代理通过正式入口调用没有强制成功或修改 Stores；纯世界运行只发出推进时间请求。简单诊断策略不冒充 LLM 自由探索或人类高强度试玩。

| 样本 | 实际结果 | 边界 |
| --- | --- | --- |
| 无代理行动，81001，三日 | 8 次跨镇货运、102 次谋生产出、65 次真实工资支付、19 次食物请求争执、1 次地区道路压力启动 | 已有机制运行证据，不代表新增内容或所有经济链连通。 |
| 无代理行动，82002，三日 | 8 次跨镇货运、109 次谋生产出、72 次真实工资支付、22 次食物请求争执、1 次地区道路压力启动 | 有数值与事实差异，尚未检验是否产生有意义的不同人生。 |
| 生成区域代理游玩 | 6 次正式行动，途经三个聚落及车场，执行现场检查与等待，共推进 14 小时 | 证明后台可以旅行和读取结果；当前可参与世界的动作仍窄，不能据此宣称世界感已建立。 |
| 第一冬代理游玩 | 7 个职责结算与 1 次成长确认，走到第 8 日，开放第一季度入口 | 旧切片的控制接通；未在本轮代理样本中继续跑完季度、跨年或所有战斗分支。 |

两组世界样本耗时分别约 93.52 与 70.56 秒，包括开局、演算和分页统计。单次推进 24 小时在约 17.95 至 42.57 秒之间。这是开发机运行诊断，不是隔离环境性能基准；同时段存在其他验证活动，不能作为前后版本性能结论。H1 将把模拟、投影和审计分开测量，也不能照此成本把多日结算直接塞入无反馈 UI。

最初的区域策略误用不存在的 `destination_id` 字段，导致在同一路线上往返。错误属于测试策略，不归咎于游戏涌现；修正为读取候选实际给出的 `destination_name` 后重跑。初轮痕迹保留，最终游玩样本以 `agent_evidence/play_checked` 为准。

## 验证与失败记录

最终共 9 个 GDScript 测试文件通过，其中新协议测试包含 51 项断言，既有相关测试为 8 个。另有 Python 真实进程测试 6 组通过，覆盖逐字节中文、畸形 JSON 后继续通信、超长/残缺帧、重复请求、JSONL 桥接、超时与退出。Godot headless 编辑器导入成功，收尾进程检查没有残留 Godot 进程。

| 验证 | 本轮最终结果 |
| --- | --- |
| agent_game_session_test | 51 / 51，`contracts_final` |
| 4 个 life_project_test | 4 / 4，`life_projects` |
| v5_playtest_ux_regression_test | 1 / 1，`ux` |
| save_envelope_roundtrip_test | 1 / 1，`native_save` |
| 2 个 world_time 测试 | 2 / 2，`time` |
| Python 管道测试 | 6 / 6，`transport_final.log` |

本轮没有重跑全项目 121 项回归，也没有三种子三十日长测；不沿用旧计数冒充本轮结果。UI 回归为 headless 自动测试，没有进行本轮 GPU 截图或人类独立试玩。

初轮失败不是直接删掉断言：

1. Windows 管道短读被当作完整缓冲。对照 Godot 4.6.3 源码确认返回缓冲未缩到实际读取长度；runner 在 Windows 按单字节读取再组帧，真实分片和截断测试最终通过。
2. 存档后可见实体顺序随字典序改变。后台投影与候选采用稳定 ID 排序，不改变实际角色、事实或正式结算。
3. 生成世界的完整精度签名不同。逐字段检查定位到 7 个事实中资源比例的末位小数，如 `0.7678571428571429` 转为 `0.767857142857143`。原生 SaveEnvelope 明确采用短小数表示以兼容旧摘要规则，故磁盘测试改按相同原生精度比较，并新增续跑检查；只读及同源行动对照继续使用完整精度。没有改动存档序列化、摘要算法或用近似比较放过人物/物品丢失。

## 参赛目标如何约束后续

已核实 [Tripothon S1 官方页](https://developers.tripo3d.ai/en/events/tripothon-s1) 要求可玩 Demo、实际游玩录屏和视觉资产板。Game 方向允许任意技术栈，工具赛道才要求使用对应工具。本轮不报名、不上传作品，也不因为活动名称包含 3D 就重写为大型 3D 游戏。

短期范围是有限区域、有限居民、真实工作与实物链、一条有撤退与代价的危险出行。世界底层先验证，再让玩家进入同一世界。美术从 H1 打样、H3 进入游戏，H4 前接受非开发者试玩；没有无限扩写固定年份或等全部世界完工再做 UI 的余地。

现有备用素材未形成统一授权清单，部分 README 只是字体说明。尚无本轮独立 Windows 发布包、可提交录屏或视觉资产板。这三项是新的硬交付目标，不是当前已交付成果。

## 后续优先项

H1 从同一生成世界的身份、时间、空间与性能基线开始，同时交付一个真实地点美术样例和早期打包冒烟。随后 H2 接通工作收入、消耗和人物处境，H3 才把它们变成有真实取舍的玩家参与方式。旧生涯夹具连续性不在本次参赛范围内整体重写，但不能再拿旧夹具切换冒充连续世界。
