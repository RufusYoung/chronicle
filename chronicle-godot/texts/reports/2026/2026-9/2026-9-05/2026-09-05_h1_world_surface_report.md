# H1 连续世界、视觉样例与运行包

日期：2026-09-05。活动阶段仍为 H1，性能门槛未通过。

## 结果与判断

生成区域已从后台夹具变成默认可打开的世界原型。现在可以跨镇和进入设施、保存整个世界、关闭后继续，在区域页看到同一组真实城镇和道路；苇岸地点美术也已经进入游戏。Windows 独立包已建立，外部 AI 可以直接操控包内程序，不需要编辑器、源码目录或屏幕操作。

这些改动改善了世界入口、空间辨识、恢复能力和可测试性。**它仍不具备完整 Demo 的游戏性**：玩家生活目标、收入与消费的持续循环、危险出行和有意义的行动取舍未完成。本轮不提高“矮人要塞式涌现”或“Steam Demo”百分比，也不拿自动测试数量抵扣玩法欠账。

下一轮先处理已经量到的运行成本，再继续 H2 的真实收入、作业和跨镇物资链。不能把七日已经能跑误写成七日已经运行得足够快或世界经济可持续。

## 已接通的内容

1. `world_bootstrap.tscn` 分派正常游戏与显式 `--agent-stdio` 入口。默认 UI 进入三聚落生成世界，不再要求按湖湾镇固定线索顺序开局。旧湖湾镇和哨站切片仍可作为回归探针，未整体重写。
2. 地点 ViewModel 统一选择生成/旧切片开局。跨镇保持同一个 SimSession；存档采用完整原生 SaveEnvelope，附带现场反馈与行动历史。先写临时文件、读回校验，再替换旧档；载入成功前不替换活跃会话。
3. 世界原型提供保存、读档、可指定种子的新世界和退出确认。恢复与覆盖需确认，启动优先继续已保存世界。错误保留旧文件，结算中不接受第二个动作，失败不自动重试。
4. 正常行动的模拟与投影放到独占 ViewModel 的工作线程，主线程只使用缓存视图。帧继续更新、显示等待提示；完成后才替换投影与恢复操作。没有使用线程同时改写同一世界。
5. 区域图读取真实聚落/道路和所属城镇，公开信息也通过 `region_map` 交给代码代理。它是拓扑示意，不是已经实现比例、坐标和地形模拟的大陆地图，也不公开远处居民的隐藏库存或目标。
6. 苇岸静态地点画通过内置 imagegen 新生成并接入区域页，保留提示词和来源。画中物件并非逐一模拟，界面明确注明；其他城镇不复用它冒充独立画面。美术样例与源码中的备用素材库分开，备用库未移动、删除或纳入导出。

## 性能诊断

机器为 Intel i7-13700H，实机渲染使用 NVIDIA RTX 4060 Laptop GPU，Godot 4.6.3。下表是开发机诊断记录；七日探针期间同时下载了官方导出模板，不属于严格隔离的硬件基准，也不是与旧版本的性能对比。

| 阶段 | 累计运行一日 | 累计运行七日 |
| --- | ---: | ---: |
| 当日 24 小时模拟 | 7.631 秒 | 36.687 秒 |
| 地点完整投影 | 0.433 秒 | 1.390 秒 |
| 持久引用审计 | 0.013 秒 | 0.025 秒 |
| 存档及完整性读回 | 1.161 秒 | 2.612 秒 |
| 存档字节 | 1,388,069 | 3,302,636 |
| 事实条数 | 621 | 1,823 |

第七日载入耗时约 1.615 秒。54 项渲染测试中，场景实例化至绘制帧约 0.845 秒，跨镇结算加投影约 1.51 至 1.80 秒，设施移动约 0.60 秒，等待一小时约 0.83 秒。前者不包括进程启动和预加载，不能据此认定完整冷启动已达标；行动样本也不足以给出可信 P95。

结果表明，当前增长主要体现在模拟与投影，不在单独的引用审计。历史变长与成本上升同时发生，但还没有逐函数证据确认具体热点。下一轮需分解快照构造、候选生成与事实/日志查询，依据测量优化，再检验普通行动 P95 和七日历史下的完整 UI。保留全部因果和数值合同，不删事实、不跳过结算、不靠增加起始钱维持表面运转。

## 修复过程中发现的问题

- 区域页和开发说明争夺最小高度，导致 720p 行动栏越界。让页面只按当前页计算高度，把非任务性的世界说明放入记录，保留现场决策和完整信息入口；实际截图复查通过。
- 地形原始英文标签挤出图节点，改为有限的中文地形标签。进入车场时直接读取地点字段不能确定所属城镇，修为复用已有城镇归属查询；新增失败样本 `surface/render_facility_failure.log`，最终 54 项通过。
- 选择资源导出遗漏 GDScript 间依赖、字体和地点画，导出命令却返回成功。改为完整运行资源导出，同时排除 `_archive`、备用素材、测试、报告和工具；导出脚本加入实际启动及标记校验。
- 发布程序没有按编辑器的外部 `--script` 探针方式执行测试，两次有界尝试超时并回收了自建进程。随后把 stdio driver 提取为共用代码，由正式 bootstrap 响应显式代理参数，再以真实包内协议验证；不把那两次尝试算作包内 UI 验收。

## 交付与复现

Windows 内部包位于项目根目录 `builds/h1-windows/`，运行 `Chronicle.exe`，保留同目录 `Chronicle.pck`。正常启动无需安装 Godot 或 Python；源码与证据入 Git，平台二进制与下载模板不入库。版本、源码是否有未提交改动及二进制摘要由包内 `build_manifest.json` 记录。包未签名、未对外提交，完整比赛录屏、声音、资产板和独立机器验收仍未完成。

复现入口：

```powershell
./chronicle-godot/tools/export_windows.ps1
Godot_v4.6.3-stable_win64_console.exe --path chronicle-godot --rendering-method gl_compatibility --script res://tests/rebuild/world_demo_surface_test.gd
Godot_v4.6.3-stable_win64_console.exe --headless --path chronicle-godot --script res://tools/world_runtime_probe.gd
$env:CHRONICLE_GODOT = (Resolve-Path 'builds/h1-windows/Chronicle.exe').Path
$env:CHRONICLE_TEST_PACKAGED = '1'
python chronicle-godot/tools/test_agent_play.py
```

导出需要 4.6.3 Windows x86_64 模板。本轮从 [Godot 官方发布](https://github.com/godotengine/godot-builds/releases/tag/4.6.3-stable) 下载并按官方 SHA512-SUMS 校验，只安装 Windows x86_64 模板。导出流程依据 [官方 Windows 导出文档](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_windows.html)。

地点画及最终提示词见 `assets/world/ASSET_PROVENANCE.md`，思源宋体上游许可和 Godot/第三方库版权已随包附带。图文与 Compatibility 是当前打样技术路线，不代表整套美术已经冻结或完成。
