# CHRONICLE 六维属性与 Demo 进度报告

日期：2026-08-12
分支：`exp/v5-player-attributes`

## 1. 当前结论

本轮修复了角色信息缺失。此前运行时玩家只有感知字段，左侧也只显示感知；力量、敏捷、智慧、魅力和体质只存在于 GDD 示例中，没有进入当前可玩构建。这是实现未完成，不是有意隐藏。

现在六维属性已经全部进入玩家快照，并在左侧持续显示：

```text
力量 7　敏捷 8　智慧 9
魅力 6　体质 8　感知 10
```

粮仓、北埠档房和雾盐旧井不再全部使用感知检定，分别改为敏捷、力量和体质。危险按钮、风险面板和行动反馈都会说明使用的属性、骰值、准备加成、合计与难度。

智慧和魅力已经是正式运行时字段，但当前还没有合适的辨识、推理、说服或交涉行动调用它们，因此不能算作已经投入玩法。

## 2. 本轮完成内容

- 按 GDD 写入六维初始值：力量 7、敏捷 8、智慧 9、魅力 6、体质 8、感知 10。
- 左侧角色摘要增加完整六维，同时保留身份、食物、健康、伤势、长期痕迹和发现物。
- 增加摘要高度，实际窗口中所有信息均可完整读取。
- 废弃粮仓朽木地板改用敏捷检定。
- 北埠水浸封存层改用力量检定。
- 雾盐旧井第二环改用体质检定。
- 三个危险按钮直接标明所用属性。
- 校准准备加成：完成粮仓准备后，即使掷出最低合法点数也能通过，保留“认真准备可靠化险”的既有设计。
- 新增属性界面验收测试，检查六维来自运行时快照而非 UI 硬编码。

## 3. 验证结果

- JSON 数据校验通过。
- 属性定向测试通过。
- 粮仓、档房、旧井的模拟与界面回归通过。
- 完整 23 步试玩路径通过。
- 全项目 Godot 测试：`55 / 55` 通过。
- 实际启动 Godot 图形窗口检查：六维、食物、健康、伤势和发现物均完整显示，没有被左侧面板截断。

## 4. 完成度估算

### 完整游戏：约 16%

已经具备世界状态、事实、痕迹、关系、物品、延迟后果、NPC 局部生活网络、湖湾镇调查切片和初步纪事等底层能力。

尚未形成完整游戏所需的大部分地区、职业与生活方式、长期人生阶段、战斗、装备、技艺、生态、人口演替、大规模内容、正式存档和完整前台。因此底层系统数量不能直接折算成完整游戏内容完成度。

### 可上架 Steam Demo：约 37%

当前最强的部分是湖湾镇短期链和底层状态闭环，最弱的部分是 Demo 后三段与发布工程。

| 维度 | 当前判断 |
| --- | --- |
| 湖湾镇状态、行动、痕迹与局部涌现 | 已形成可玩的内部切片 |
| 第七哨站五年服役 | 尚未形成正式可玩内容 |
| 五年后回到湖湾镇的长期回声 | 尚未形成闭环 |
| 人生阶段结算与最终纪事 | 有局部原型，未达到 Demo 结尾要求 |
| UI 与行动反馈 | 可内部试玩，仍缺正式菜单、设置和系统化易用性打磨 |
| Windows 导出与 Steam 构建 | 尚无 `export_presets.cfg`，尚未建立独立 Demo 构建 |
| 存档与恢复 | 当前可玩场景明确没有正式存档 |
| 外部玩家 QA 与商店素材 | 尚未开始系统化准备 |

因此距离“公开上架的 Steam Demo”约还有 `63%`。这不是工期百分比：后半程包含大量内容制作、反复试玩与发布工作，耗时通常不会与百分比线性对应。

Steam 官方把 Demo 视为独立 App ID，需要自己的构建、Depot 和发布清单；如果使用独立 Demo 商店页，还要准备仅针对 Demo 内容的说明、预告片和至少五张截图。商店页与产品构建提交后还要经过审核。因此当前 Godot 内部可玩构建不能直接等同于可上架 Demo。

## 5. 下一阶段

下一轮不应继续只增加角色卡数字，应让属性改变可行动性：

1. 为行动候选增加通用的属性门槛和属性检定条件，不把判断写死在单个剧情场景。
2. 让智慧参与记录辨识与因果推断，让魅力参与请求、谈判和关系行动。
3. 让属性不足时显示可理解的受限原因，而不是让选项无声消失。
4. 完成这一小层后，开发重心应转向第七哨站长期项目，因为它是 Steam Demo 当前最大的内容缺口。

本轮让六维从设定表进入了实际构建，但还没有完成完整角色成长系统。下一阶段的验收应以“属性改变了玩家能看到和能执行的行动”为准，而不是以新增字段数量为准。
