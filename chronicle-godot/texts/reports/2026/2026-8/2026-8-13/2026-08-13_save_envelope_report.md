# Chronicle SaveEnvelope 存档与阶段交接报告

日期：2026-08-13

分支：`exp/v5-save-envelope`

对应计划：阶段 5.5，步骤 4

## 1. 本轮结果

步骤 4 已完成。项目此前只能导出用于测试的 SaveEnvelope seed，不能从文件恢复运行；现在已经具备带版本的正式存档、迁移、失败校验和继续演算能力。

本轮完成后：

- 所有运行 Store 都有显式 `to_save_data()` 与 `load_save_data()` 边界。
- SaveEnvelope v1 保存世界身份、世界时间、RNG、当前地点、长期项目 runtime、全部 Store、世界日志和 Definition 清单。
- 存档可在内存中恢复，也可写入和读取 `user://` 文件。
- 湖湾镇完成后的玩家经历会显式交接到第七哨站，不再由场景切换假装人生连续。
- 载入后行动候选会重新计算，不保存 Snapshot、候选、库存视图或市场视图等派生结果。

## 2. 保存与载入顺序

正式载入按固定阶段执行：

```text
读取 JSON
校验 schema_version 与 source_kind
迁移旧 schema
校验 SHA-256 摘要
按静态 fixture 和规则重建 Definition
核对 Definition manifest
按依赖顺序载入全部 Store
校验跨 Store 引用
恢复世界时间、RNG、会话游标和长期项目 runtime
重新生成 Snapshot 与行动候选
```

任何阶段失败都会返回明确的 `phase` 与错误信息，并清空失败会话，避免把半份存档留成可继续运行的世界。

RNG 状态以十进制字符串进入 JSON，避免 64 位整数在 JSON 数值往返中丢失精度。摘要针对规范化后的 payload 计算，用于发现文件损坏或未经重算的修改。

## 3. Store 与派生数据边界

进入存档的运行真值包括：

- Entity、State、Fact、Relationship、Memory；
- Trace、Rumor、Pressure、Obligation、Exchange、Deferred Consequence；
- Talent、Trait、Mark、Skill 实例；
- ItemInstance 与 EquipmentLoadout；
- Chronicle 与 InvestigationLead；
- SimWorldLog 与 LifeProject runtime。

不进入存档的派生数据包括 Snapshot、当前行动候选、InventoryView、MarketStockView、UI 状态和测试断言。载入后重新生成这些结果，是本轮候选一致性测试的一部分。

## 4. 湖湾镇到第七哨站

审计发现，原先湖湾镇结局进入第七哨站只切换了场景，新 Session 会重新使用前哨初始 fixture，玩家调查经历和实际物品没有被带过去。这不满足步骤 4 的验收条件。

本轮新增一次性人生阶段交接：

- 只有湖湾镇真实完成时才能构造交接；重开试玩后残留的完成信号不能跳关。
- 交接携带玩家相关状态、经历事实、关系、记忆、角色特征、物品、编年史和世界时间。
- 物品来源涉及的人物实体会作为引用依赖一并携带。
- 湖湾镇的整套地区压力、地点状态和调查运行态不会复制到第七哨站。
- 第七哨站接收交接后立即使用自己的规则与 Definition，并可保存为同一种 SaveEnvelope。

自动化测试确认玩家的旅行口粮、旧粮仓铜牌、雾盐呼吸印记、冬斗篷和关键调查事实都会进入第七哨站，并在保存、载入后保持一致。

## 5. 迁移与拒绝策略

当前迁移注册表支持 v0 到 v1。它会补齐 v1 元数据与完整性结构，再进入和正式存档相同的校验链。

以下输入会被拒绝：

- 高于当前实现的未来 schema 版本；
- 不允许的 `source_kind`；
- 摘要不匹配的文件；
- 缺失必需 Store 或 Definition 的文件；
- 关系、记忆、物品、装备和编年史存在悬空引用的文件。

正式 UI 入口只允许加载 `player_save`。`test_fixture` 与 `migration_fixture` 仍可用于自动化验证，但不能伪装成玩家存档。

## 6. 自动化验证

新增存档专项测试，覆盖：

- 第一冬执行一次职责后的内存往返；
- `user://` 磁盘写入与读取；
- v0 到 v1 迁移；
- v0 容器类型损坏时返回迁移失败，不触发脚本错误；
- 摘要篡改拒绝；
- 摘要有效但跨 Store 引用损坏时拒绝；
- 未来 schema 拒绝；
- 原会话与恢复会话执行下一次相同行动后，结果、Store 和世界时间一致。

内部试玩端到端测试也加入湖湾镇真实完成、阶段交接、第七哨站保存恢复和重开后拒绝陈旧交接的检查。

测试环境：Godot 4.5.1，Windows，headless。

结果：全项目 `65 / 65` 个测试脚本通过，输出无 `SCRIPT ERROR`。

## 7. 改善与限制

最重要的改善不是多了一个 JSON 文件，而是世界真值现在可以在进程结束后恢复，并继续产生和原会话一致的下一步结果。湖湾镇和第七哨站之间也第一次拥有可验证的人生连续性。

仍未完成的发布级能力：

- 玩家可见的存档槽、覆盖确认、删除、自动存档和载入界面；
- Steam Cloud 与跨设备冲突处理；
- v1 之后的真实历史版本迁移；
- 原子替换、备份存档和崩溃恢复策略；
- 对存档内容的密码学签名。当前摘要用于完整性检查，不是防作弊安全边界。

## 8. 下一步

进入步骤 5。使用第一冬验证最小系统内容：让一个交易面同时读取实际库存和粮食压力，让行动风险进入结果档位，并在七日结束时生成一次由经历事实支撑的成长候选。存档合同继续作为这些系统的持久化边界，不再为新玩法建立平行真值。
