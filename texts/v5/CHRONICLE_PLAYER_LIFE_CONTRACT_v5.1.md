# 正式旅人与共同生活合同

2026-09-11。属于 RF6，不另开执行计划。实现见 `scripts/sim/player/player_life.gd`，当前范围不等于完整人生或参赛 Demo。

## 权威状态与时间

- 仅显式开启 `player_life_version=1` 的新世界使用本规则。原生 bootstrap 保存根配置、编译标记和身体所属聚落，加载时交叉校验。旧世界不会被自动赋予饥饿、工作或分小时旅行。
- 玩家仍使用 EntityStore、StateStore、ItemStore 和统一事务。身体位置是 StateStore 的 `location_id`，会话位置是其界面投影，不新增另一份库存或钱包。
- 玩家不交给 NPC 自主行动器。本人选择后，适配器调用同一个需求、配方、资源、市场和维修执行器；采用相同工具能力与资源权限。
- 每六小时加深一级饥饿；吃掉一份实际食物降低两级。旅行每小时推进世界，抵达前不能隔空工作或交易。新规则不再额外收取旧路线的固定口粮费。
- 此处未实现饿死、永久死亡或完整营养模型。身体、时间、食物和恢复存在约束，不应因此宣称完整生存模拟。

## 可选择的生计

| 行动 | 真实投入与结果 | 失败边界 |
| --- | --- | --- |
| 就地采食 | 四小时、当地公用资源；至多四份归本人携带 | 时间、健康、疲劳、资源和本地使用权 |
| 采收短工 | 同一采食配方；产物归雇主，完成时由雇主转移三枚铜币 | 雇主须在场、有钱；离开、遇险或缺料会中止，无免费工资 |
| 专业作业 | 当前聚落现有无薪生产配方；物品/资源投入、实际工具磨损，产物归本人 | 工具不合用或损坏、材料不足、未到现场、身体与工时不足 |
| 当面购买 | 现有 Market 报价和 ItemStore 现货；卖家保留口粮和自用工具 | 无现货、卖家离场、支付不足、库存已变 |
| 工具维修 | 共用 maintenance 配方，用实际本地材料恢复有限耐久 | 当前规则只修耗尽工具，维修次数有限，不是无限翻新 |
| 休养 | 时间、实际需要的食物与原危险恢复规则 | 缺粮不能治疗；疲劳可以下降，不能在交锋或途中休养 |

短工的三铜币、八份以下雇主库存门槛是可逆的 v1 工程假设，尚未完成市场平衡。没有完整雇佣合同、招工信息市场或保证每天都有活。只见到一个短工选项，不代表世界承诺它必定完成。

未完工时数保存在既有 `subsistence_elapsed_hours`，以当前作业意图和地点区分。入夜可中断，原地选择同一作业可续作；换活重新准备。测试和代理必须用成品、磨损或维修事务确认完成，不能用“按钮成功返回”或控制器阶段名代替。

## 所有权与知情

收货人必须在共享配方规划叠堆/创建物品之前确定。短工不能先把物品加到玩家的同类堆，再仅修改新建物品的归属。测试覆盖空行囊与预先已有同类食物两种情况。

本人参与过的粮食补充，经粮柜和实际分配保留批次来源。居民只有在与旅人同地、亲自经历了后续进食或存粮时，才可谈及该结果；问过同一贡献和同类结果后不反复显示。远方私人事件不自动成为旅人知识。

混合堆的来源是可追溯的批次关联，不是每份食物的独占谱系，也不单凭关联宣称所有后果由玩家造成。实际因果改善另用同存档、同绝对时间的旁观对照验证。

等待反馈只呈现现场可见事件，不播报全世界的进食人数。库存名称、数量与耐久可供 UI 和后台合法代理读取；原始世界 stores 仍不能在 play 模式被全知检查。

## 验证口径

- 聚焦合同覆盖自然作业、购买、断粮后采食、真实货币转移、工具全寿命、原生存档、途中恢复和旧世界隔离。
- 模拟干预反例单独标记，包括给定测试预算、耗尽资源、在途雇主和损坏存档。测试预算从已有资金转移，不额外造币。
- 后台合法游玩从相同原生存档分支，仅使用公开观察和当时开放选项。完成后才读原生 stores 做审计；不等于人类试玩。
- 实际渲染验证按钮回调、行动说明、当面询问后的具体信息及 720p/900p 可达性，不替代 RF7 独立玩家评价。
- E3 的机械差异、后果可理解性、15–25 分钟首次体验及纯数据扩展分别报告，不把其中一项通过扩大为 RF6 全部完成。
