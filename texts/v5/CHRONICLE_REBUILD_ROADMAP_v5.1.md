# Chronicle v5.1 重构路线图

## 1. 文档定位

本文件是 Chronicle v5.1 重构阶段的开发路线图。

它不替代主 GDD，也不替代系统模块拆分文档。

它的作用是回答：

```text
现在从哪里开始重构？
每一阶段做什么？
每一阶段做到什么程度算完成？
哪些系统先不碰？
什么时候才能让 Codex 执行长工程？
```

当前重构原则：

```text
先搭前台承载面。
再接最小世界闭环。
再接生涯与长期项目。
再接阶段结算与纪事。
最后再细化战斗、装备、食物、技艺等复杂系统。
```

---

## 2. 重构总原则

Chronicle v5.1 不应一次性重写完整游戏。

当前系统太复杂，如果把地点、状态、线索、生涯、长期项目、战斗、装备、食物、职业、关系、传闻、传记同时交给 Codex，会导致逻辑混杂、边界失控、难以测试、难以回退。

因此 v5.1 采用积木式开发：

```text
一个阶段只验证一块核心能力。
每块能力有独立场景、独立数据、独立脚本、独立测试。
不污染旧主界面。
不提前接入完整系统。
每完成一块，再决定下一块。
```

## 4. 分支与目录策略

### 4.1 不直接污染旧主线

v5.1 重构阶段不直接修改旧主界面，不直接接入旧 Demo。

禁止直接修改：

```text
chronicle-godot/scenes/ui/mainui.tscn
chronicle-godot/scenes/ui/story_player.gd
chronicle-godot/scripts/gen/world_generation_v03.gd
chronicle-godot/project.godot
chronicle-godot/素材包/
```

除非后续有明确单独指令。

### 4.2 新建 rebuild 目录

v5.1 重构原型优先放入：

```text
chronicle-godot/scenes/rebuild/
chronicle-godot/scripts/rebuild/
chronicle-godot/tests/rebuild/
chronicle-godot/data/rebuild/
```

这样可以做到：

```text
旧 Demo 保留
新原型独立
失败可回退
后续可选择迁移
```

### 4.3 旧代码只作为参考

旧 LakeTown、LivingSurface、WorldViewer、HistoryVariation 等代码可以参考，但不要直接混入新架构。

旧代码价值：

```text
湖湾镇因果链样板
LivingSurface 卡片样板
世界状态观察器样板
多 seed 历史差异样板
饥饿闭合规则样板
```

但 v5.1 第一阶段应先做干净的前台承载面。

## 5. 重构阶段总览

v5.1 重构建议分为八个阶段。

```text
阶段 0：文档入口与执行纪律
阶段 1：地点局面主界面原型
阶段 2：湖湾镇最小状态闭环
阶段 3：线索与追寻系统原型
阶段 4：生涯面板与长期项目入口
阶段 5：第七哨站长期项目原型
阶段 6：人生阶段结算
阶段 7：个人纪事导出
阶段 8：再进入战斗、装备、食物、技艺等细化系统
```

当前已完成阶段 0 的基础入口整理。

## 7. 阶段 1：地点局面主界面原型

### 7.1 目标

建立 v5.1 重构的第一个可运行开发场景。

本阶段不是做完整 Demo，而是做 Chronicle 的前台承载面。

需要证明：

```text
玩家能看到地点局面。
玩家能看到角色状态。
玩家能看到地区状态、线索、地点。
玩家能点击地点节点。
玩家能点击行动。
行动能刷新局面。
线索能进入列表。
线索能打开行动卡。
生涯面板可以打开占位。
```

### 7.2 目标场景

建议新增：

```text
chronicle-godot/scenes/rebuild/v5_location_foundation_viewer.tscn
```

配套脚本：

```text
chronicle-godot/scripts/rebuild/v5_location_foundation_viewer.gd
chronicle-godot/scripts/rebuild/v5_location_foundation_state.gd
chronicle-godot/scripts/rebuild/v5_location_foundation_view_model.gd
chronicle-godot/scripts/rebuild/v5_location_foundation_actions.gd
```

配套数据：

```text
chronicle-godot/data/rebuild/lake_town_location_foundation.json
```

配套测试：

```text
chronicle-godot/tests/rebuild/v5_location_foundation_state_test.gd
```

### 7.3 UI 结构

本阶段主界面结构：

```text
顶部：背包 / 角色 / 世界 / 生涯 / 设置
左侧：角色状态摘要
中央：地点局面
右侧：地区状态 / 线索 / 地点
底部：行动选项
```

### 7.4 初始地点

本阶段使用湖湾镇作为静态原型地点。

初始局面应包含：

```text
角色：阿尔维斯，26 岁，流浪者，湖湾镇
地点：湖湾镇
事件切面：老陈铺子没开门，陈米抱着旧布袋
地区状态：粮食紧张、治安不安、商路受阻、人心压抑
可进入地点：老陈铺子、市场、码头、守卫所、废弃粮仓
```

### 7.5 最小行动

至少支持：

```text
走近陈米
查看涨价告示
去市场打听粮价
前往废弃粮仓
在湖湾镇停留一月
离开湖湾镇
```

每个行动至少产生一种变化：

```text
中央叙述变化
线索增加
地区状态变化
角色状态变化
可用行动变化
行动历史增加
```

### 7.6 最小线索

至少支持一条线索：

```text
[线索] 粮价明天再涨一次
```

点击后打开线索行动卡。

线索行动卡应显示：

```text
标题
来源
可信度模糊描述
可行动项
是否可加入追寻
```

### 7.7 生涯面板占位

点击顶部“生涯”后，至少显示：

```text
可开始的人生方向：
- 漂泊
- 定居
- 营生
- 追寻

听说过但尚未开启：
- 北境边境巡逻者
- 王都抄书学徒

已完成经历：
- 暂无

纪事：
- 暂无
```

### 7.8 禁止事项

阶段 1 不做：

```text
完整战斗
完整装备
完整食物
完整技艺
完整长期项目
完整传记
AI 文本生成
旧 mainui 接入
```

### 7.9 验收标准

阶段 1 完成后，应满足：

```text
能打开独立 rebuild 场景
左侧显示角色状态
中央显示地点局面
右侧显示地区状态、线索、地点
底部显示行动
地点节点可点击
至少 3 个行动可点击并刷新 UI
至少 1 条线索可获得
线索行动卡可打开
生涯面板占位可打开
不修改保护文件
有测试或测试说明
有阶段报告
```

## 8. 阶段 2：湖湾镇最小状态闭环

### 8.1 目标

在阶段 1 的前台承载面上，接入一个最小世界状态闭环。

不是静态按钮变化，而是让湖湾镇出现最小因果链：

```text
粮食压力
↓
粮价上涨
↓
老陈压力升高
↓
陈米饥饿升高
↓
陈米拿到发霉麦子
↓
老陈关店
↓
玩家撞见局面
↓
玩家介入
↓
关系、痕迹、地区状态变化
```

### 8.2 本阶段要做

新增最小对象：

```text
old_chen
chen_mi
ma_shen
liu_zhangfang
old_chen_shop
abandoned_granary
spoiled_grain
```

新增最小状态：

```text
粮食压力
粮价趋势
家庭压力
陈米饥饿
陈米恐惧
腐败食物
老陈关店
废弃粮仓状态
```

新增最小行动：

```text
给陈米食物
问粮从哪来的
举报她
装作没看见
低价收购
```

### 8.3 阶段 2 验收标准

阶段 2 完成后，应能证明：

```text
陈米局面不是随机事件卡
它能追溯到湖湾镇状态
玩家行动会改变陈米、老陈、地区、线索、痕迹
行动后世界状态可继续推进
```

## 9. 阶段 3：线索与追寻系统原型

### 9.1 目标

把阶段 1 的线索列表从 UI 占位推进为可用系统。

实现：

```text
线索获得
线索按地点折叠
线索可信度模糊描述
线索行动卡
线索升级为追寻
追寻进入生涯面板
```

### 9.2 示例

```text
[线索] 废弃粮仓的粮粉
[线索] 北路迟到的商队
[追寻] 北方龙影
```

### 9.3 阶段 3 验收标准

玩家能够：

```text
从场景文本获得线索
在线索列表查看
点击线索打开行动卡
选择将线索加入追寻
在生涯面板看到追寻方向
```

## 10. 阶段 4：生涯面板与长期项目入口

### 10.1 目标

让“生涯”从占位面板变成可用的前台人生入口。

实现：

```text
可开始人生方向
听说过但未开启的人生可能
当前长期项目
已完成经历
纪事子目录
```

### 10.2 本阶段不做完整长期项目

阶段 4 只做入口和结构，不做五年服役那种完整内容。

可先支持：

```text
在湖湾镇停留一月
在湖湾镇定居一季
追寻北方龙影的第一步
```

### 10.3 阶段 4 验收标准

玩家能够：

```text
打开生涯面板
看到当前可开始人生方向
看到听说过但未开启的人生可能
选择一个短期长期项目
项目结束后进入已完成经历
```

## 11. 阶段 5：第七哨站长期项目原型

### 11.1 目标

实现第一个真正有厚度的长期项目原型：

```text
第七哨站服役五年
```

### 11.2 核心结构

长期项目不只是跳过时间，而是：

```text
年度摘要
固定人物
重复仪式
关键节点
世界背景小结算
中途退出机会
阶段结算
离别文本
```

### 11.3 固定人物

至少包含：

```text
队长罗恩
新兵伊莱
厨子玛塔
军医赛拉
老兵霍克
```

### 11.4 年度结构

参考：

```text
第一年：新兵之冬
第二年：雾线巡逻
第三年：饥饿之年
第四年：黑旗来袭
第五年：退役前夜
```

### 11.5 验收标准

玩家应能感到：

```text
自己真的在第七哨站度过了几年
身边人发生了变化
重复仪式有时间感
选择产生回声
离别文本能回收前文记忆
```

---

## 12. 阶段 6：人生阶段结算

### 12.1 目标

把长期项目和重大人生阶段压缩成成长、伤痕、关系、特质和记忆。

### 12.2 结算结构

```text
展示这段时间发生过的关键事实
↓
自动获得必然留下的特质、伤痕、关系、装备历史
↓
展示属性成长候选
↓
展示人生取向选择
↓
结算 NPC、地点、组织、地区状态
↓
进入下一段人生
```

### 12.3 验收标准

玩家结束一段经历后，应看到：

```text
这段人生发生了什么
自己因此获得了什么
自己因此失去了什么
世界因此改变了什么
下一段人生可以怎么过
```

---

## 13. 阶段 7：个人纪事导出

### 13.1 目标

实现第一个能引用真实经历的个人纪事导出。

### 13.2 要求

个人纪事不是事件列表。

必须引用：

```text
真实地点
真实 NPC
真实选择
真实伤痕
真实关系
真实遗物
真实阶段结算
```

### 13.3 输出格式

优先支持 Markdown 导出。

### 13.4 验收标准

纪事读起来应像一段奇幻小说式个人纪事，而不是：

```text
第1年：做了某事
第2年：获得某物
第3年：死亡
```

---

## 14. 阶段 8：复杂系统细化

只有当前台承载面、湖湾镇闭环、生涯入口、长期项目、阶段结算、纪事导出跑通后，才进入复杂系统细化。

后续系统包括：

```text
战斗系统
装备系统
食物与料理
职业与技艺
天气
完整关系网
完整传闻传播
遗产与赝品
AI 文本叙事层
```

这些系统应逐个写系统规格文档，不要一次性全部实现。

---

## 15. Codex 长工程策略

允许 Codex 执行 7–8 小时长工程，但必须满足以下条件：

```text
已有路线图文档
已有当前阶段 UI Flow 或系统规格文档
任务范围只覆盖一个阶段
每个检查点提交一次
每个检查点有测试或报告
禁止修改保护文件
禁止自由扩展到未授权系统
最终写报告
```

第一个适合长工程的任务是：

```text
阶段 1：地点局面主界面原型
```

不是：

```text
完成整个 Chronicle Demo
```
