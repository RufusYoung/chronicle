# 跨用途作业与自主取舍合同

2026-09-08。约束当前 RF1 至 RF3 实现，不是第二份活动计划。顺序与验收仍见 [世界优先计划](CHRONICLE_WORLD_FIRST_PLAN_v5.1.md)。不改变原设定、图文冒险方向或既有真值层。

## 启动与版本

正式新世界显式设置 `work_rules_version: 1`，并启用既有家庭生计依赖；规则来源为 `chronicle-godot/data/sim/raw/work_rules/echo_port_work_rules_v1.json`。后台协议只开放白名单组合 `scenario="echo_realm"`、`economy_variant="work_framework_v1"`，不开放任意配置或物品写入。UI 新世界勾选对应实验项。

配置、生成后的作业配方、候选权重、初始工具与货柜进入原生 bootstrap。内容包 v6 只为准确的旧定义清单增加 `daily_intent_id` 和 `work_elapsed_recipe_id`；旧世界不因升级包而增加工作规则或初始工具。旧仓储 v1 与旧生活流程继续回归。新数据必须经过启动校验，不能凭少几个定义就冒充旧清单。

## 对象与作业

继续使用 Entity/State/Item/Resource/Fact Store、Effects、Transactions 和 SaveEnvelope。没有第二套钱、背包、工时或事件历史。

| 输入 | 已支持的语义 |
| --- | --- |
| `product_query` | 按已有产物能力/标签选择要调整的生成作业；不按 NPC 姓名分支。 |
| `work_recipe.version / recipe_id` | 配方版本和稳定身份；更换配方不能套用另一配方的未完工时。 |
| `item_inputs` | 消耗有实际持有者的物品实例；支持多个栈，不可重复使用重叠数量。 |
| `tools` | 保留而不吃掉工具；每次完成作业扣耐久。多件同栈先拆一件，只磨损实际使用的那件。 |
| `resource_inputs` | 继续读取原 ResourceStore 数量与使用权限；不是自动生成的材料。 |
| `repairs` | 消耗材料和工时，给自有损坏工具恢复有限耐久，按同一物品履历限制次数。 |
| `products` | 已注册且非货币的物品，按定义栈上限生成。耐久工具不合入旧工具来刷新耐久。 |
| `work_interval_hours` | 实际到场作业时数；途中、刚抵达、休息不计工时。 |

物品查询支持 `item_def_id`、`tags_all`、`tags_any`、`capabilities_all`，组合时取约束交集。无可用定义、未知查询语义、无投入产出、货币产出、重复资源条目、无效数量和无磨损工具配方必须失败。它没有支持任意脚本表达式或尚不存在的物理能力。

工具和物品投入只从本人携带物、本人到场的自有货柜读取。缺原料、工具耗尽、没有权限、本人不在场或库存满时，不能产生免费产物。提交失败不能遗留部分磨损、扣钱或履历。不同人的交易串行提交并重新读取原 Store；同一件货物的两个旧报价只能成功交割一次。

## 储存、购买与用途

仓储 v2 从物品定义派生可交易非货币的储存范围，使用同一个固定货柜实体。食品取用另要求 `food` 和 `consume`；不是把所有货物都当成口粮。货柜有主人、位置和容量，主人离开后不自动送货，也不会跟随换岗移动。

捕捞使用绳具，制绳也使用一件张紧绳具；工具生产因而也有自用和出售的取舍。每名对应工人在新世界开始时显式拥有一件工具，之后没有免费补发。当前修补参数为 2 小时、1 份实际纤维资源、恢复 2 耐久、每件限一次，属于有限范围的暂定平衡值，不宣称物理写实。

居民只知道本地或邻接聚落有哪些供给作业点，不预先读取远方库存。到场后才检查卖家本人、货柜余货、商品条件、自己实际携带的钱与报价。卖家先保留本人作业所需的一份工具/投入，再出售余货。没有现货或买不起会留下带时效的亲历失败，六小时内不反复向同地询价。取自己的备用品不需要付款。

物品来源通过原实例履历关联。合并的食品库存保留各批投入来源，这意味着“这批库存含某次生产”，不意味着能证明某一口食物唯一来自哪次劳动。工具生产、交易、实际使用则核对具体实例或合法拆栈后代；不能只按同品种名称串故事。

既有付费送粮继续使用本人货物、封存运费、真实道路与到家交割。本轮不是任意商品的通用承运市场，也没有自动保证盈利的商人。

## 自主目标

原有上工、采购、低效采食、休息、照护、运输等适配器提供合格候选，由已有 NPC 决策排序器统一选出当前目标。增加维护和补货候选，不再让最后一段过程代码固定覆盖前面的决定。

评分读取需要、已知家人处境、路程、疲劳、未完工时和继续当前行动的代价。无班可休息与身体撑不住必须休息分开；正常专业工作可用时，不把低产量的同业徒手劳动当作更好选择。工作受阻后可以寻求替代口粮，但仍要有权限和实际时间。

短程计划由目标地点、在途状态、意图和未完工时组成。出行沿已有道路分段，抵达后重选，途中不能瞬移或同时做工。休息后同配方可以继续，更换配方重置原作业进度。当前不是任意深度的前置任务搜索器；个性仍主要通过现有照护/出行资格影响候选，不宣称所有人格字段都进入效用函数。

## 扩展证据与边界

RF1 第三个产物试验在受控 fixture 中提供两栈鲜鱼原料，只改配方数据生成 22 份旅行口粮，验证实际原料消耗、工具磨损、20+2 入库、领取和进食。原料属于测试注入，不能称为自然经济或玩家行为。没有增加旅行口粮专用运行时分支，但也没有证明任意新职业会自行学会任意配方。

自然样本与机制关闭对照见 [联调记录](../../chronicle-godot/texts/reports/2026/2026-9/2026-9-08/2026-09-08_work_framework_working.md)。最终阶段报告另列实际发布源与包。后台无代理行动、合法代理操作、程序驱动 UI 渲染与真人游玩分别记账。

后续必须处理而未在本轮冒充完成的范围：长期供给与家庭缺粮、跨镇利益/通行规则、换岗后的固定库存交接、非生存交往、危险与玩家职业。新增能飞行、腐败、伤害器官或其他全新用途的定义仍需要实现消费者；RF6 的完整纯数据扩充门槛没有提前通过。
