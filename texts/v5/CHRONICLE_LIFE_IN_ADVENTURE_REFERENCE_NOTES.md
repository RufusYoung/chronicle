# Life in Adventure 安装包研究与 RF6 整改

日期：2026-09-24。用途是学习可执行的设计结构，不把另一游戏的内容或代码变成 Chronicle 的资产。本文件补充活动计划，不是第二份执行计划。

## 证据与边界

- 用户提供 `base.apk.1`，128,299,118 字节；SHA256 `4E1A32ED5C6D261A5DEF62DE2A26BB9B37AF752775BA82F47E12B2B0FF8E36D8`。
- PlayerSettings 表明产品为 StudioWheel 的 Life in Adventure，版本 1.2.23；包内有 Unity 数据、ARM64 IL2CPP 库和 metadata v31。
- 实际只读解析 ZIP、Unity 对象和 JSON TextAsset，没有安装或执行 APK，没有访问其服务器、账号或付费接口，没有绕过授权。
- 使用 [UnityPy 官方工具](https://github.com/K0lb3/UnityPy) 1.25.3 读取数据。提取物、工具环境、原生存档副本都在忽略目录 `work/adventure-rework/`，不提交原游戏的故事、译文、图片、声音或代码。
- 已读数据结构并不等于恢复了全部运行代码。条件和概率字段含数字编码；在未核实解释器前，不推定编码的含义、实际抽选频率或奖励概率。

| 主线事件 | 1054 | 目标关联、条件、分支与后续节点 |
| 支线事件 | 907 | 支线标识、条件与分支 |

| 特质 / 能力 / 怪物 | 44 / 168 / 184 | 条件能力、效果、敌人参数与类别 |

五类事件各有八份语言数据，逐类 ID 集相同，不能将八份译文算成八倍内容。节点包括后续节点，不能说成 3049 个互不相干的故事；物品记录也不能全算成装备或当场可取得内容。

普通事件 609 个节点中，314 个有两个选择，177 个有三个选择；不是把所有可能行为平铺成几十张卡。1525 个选项对应 2251 个结果记录，其中 463 个选项有多个结果。结果含 `required/chance/nextEvent/type/text/reward`，能把条件、选择、结算和后续分开。多个结果不必然代表随机分支，也可能由不同条件选中。

普通事件有 860 条非负后续节点引用，其余多为负值控制码；具体控制码语义未从运行代码确认。已阅读样本能看到可放弃的岔路、休息中的意外、物品或人物处境影响的应对。原作的重要优势是有组织的、足量的作者内容与条件分支，不能据此称其为矮人要塞式世界模拟。

## 对 Chronicle 的诊断

1. 当前 `local_incident_options.gd` 仅支持“磨损绳具”和“有人缺粮”两个条件，主要包装现有休息、进食、采集、工作、分粮和售粮。换标题没有增加决策维度。用户的“全程休息找食物”与代码一致。
2. 底层资源和 NPC 活动会变化，但玩家缺少值得追寻的目标。取得十二件编织装备不能替代探险、陌生发现、风险、关系以及有价值的归来。
3. 吃东西、等待、工作、交谈大多整小时结算。大量饥饿管理吞掉一天，同时夜间供给/社交缺席，造成短日循环；需要一起调整体验节奏与可用活动，不能只多发口粮。
4. 世界危险每轮推进一小时，期间 NPC 也可攻击、威胁也可吃饱退去。界面仍显示玩家本回合的“继续交锋”，缺少时段末的明确原因，容易误认为点击固定次数自动结束。
5. 卡片按物品实例乘以对象逐项展开，完整作业条件和代价重复显示；内容增多反而削弱选择。需按意图分组，决策层只放当前关键区别，详细数值与过程随时可读。

## 迁移原则与当前验收

| 学到的结构 | Chronicle 原创实现方向 | 反证/验收 |
| --- | --- | --- |
| 普通、支线、宝藏、战斗分族 | 同一世界增加短发现、援助/交易、环境冒险与夜间生活；并非每件事都接主线 | 不能所有选项最后都落到找食物；连续短程游玩能选择不同目的 |
| 少量直接选择 | 主界面按意图折叠，相同意图再选对象、物品；不因打开菜单消耗时间 | 唯一物品/收件人仍可识别，过时选择被正式执行器拒绝，无双重结算 |
| 条件与结果分离 | 候选从地点、昼夜、已知事实、物品/人物状态产生；结算复用正式事务 | 人不在、库存不足、已解决、风险消失时，不能靠文本照样成功 |
| 结果继续进入后续节点 | 原生事实、物品、关系、地点可用性决定后续机会 | 跳过/失败与介入后的合法行为出现实际差别，不只是结尾文案不同 |
| 丰富作者内容 | 先实现一组可复用语义，再填原创片段与有限后续 | 第三个定义可用同一执行机制；新语义明确算工程，不宣称纯填表即可无限涌现 |
| 奖励与成长 | 消耗准备、承担风险、取得有来源的物品/知识/关系，再用于新选择 | 不能无穷刷固定奖励，不向 NPC/市场凭空扣款或增货 |

世界规则保持独立运行；冒险内容层负责让值得注意的状态成为可理解、可选择的事件。允许原创作者片段，允许普通小事自然结束；不把所有故事预定给主角，也不指望纯生存模拟自动生成有趣冒险。

当前属于 RF6 失败整改，尚未通过新的可玩性验收。下一阶段模型建议 GPT-6 Astra／极高：整合事件条件、真实后果与清晰呈现，不需要无界反编译。
