# 前五轮整合修补合同

2026-09-21。服务于 RF1-RF5 缺口修补，不增加第九轮，也不替代主计划。本文件描述实现约束；整体验收结果另记，受控测试通过不等于自然世界验收通过。

## 版本与入口

- 新世界显式使用 `integration_rules_version=1`；后台合法操控入口为 `economy_variant="world_integration_v1"`。依赖沿岸内容 v2、身体 v1、玩家生活 v2、社区交往及作业规则。
- UI 创建沿岸生活整合新世界采用该版本。已经保存的世界继续使用其内嵌 bootstrap，不自动添加装备、协商或危险觅食规则。
- 定义保存于 `chronicle-godot/data/sim/raw/content/echo_port_integration_v1.json`，原生存档携带定义及编译指纹。加载时核对定义、作业、选择、危险和交往规则。定义注册仍使用原 Registry；物品、装备、钱、资源、记忆仍使用原 Store 与事务。

## 装备与供需

本次增加绳结短鞭和苇编护衣两种低阶纤维制品。短鞭主手位、耐久 12、近战进攻 +2；护衣外衣位、耐久 16、战斗防守 +2。它们是固定定义与固定条件修正，不是随机词缀、稀有度或无限战利品系统。

工匠用既有有限芦苇资源制作，保留并磨损一件绳具，不把唯一工具当成材料吃掉。角色从本人随身物品或同地点的自有货柜穿戴，不能远程取货。已有穿戴不重复刷事实；正在交锋或旅行的人不能在这一阶段换装。

亲见过危险的成年人会考虑护衣、武器，未听说/未亲见的危险不会凭空形成该采购需求。这里沿用过去经历作为防身动机，不把过期危险记忆当作当前威胁位置情报。选装评分目前只比较实际可用的正向战斗修正与耐久，不宣称复杂战术配装。

交易仍要求买家、卖家和实物在场，支出买家的真实钱，转移同一物品；卖家正在穿戴的物品和必要作业工具被保留。换下后随身携带的备用装备也进入当面报价，避免生产评分认为有余货、市场却只看货柜的矛盾。顾客当面询购缺货时，只记录实际在场听到的人。工匠根据这类有限时效的信息考虑生产，已穿戴自用品与可售余货分别计数，破损物品不能充当完好的可售库存。它不是全知需求排行榜，也没有欠款预订或保交付承诺。

纤维装备耐久降至 0-3 可在当地有材料的作业地修补，每次耗费真实资源与两小时劳动，恢复 4 耐久，最多两次；修补次数来自既有维修事实。旧绳具的“坏到零才修”规则不被改写。达到上限后只能保留损坏品或另行购买/制作替代品。

遮光巡灯在新世界撤离合同中获得正确的 `combat_retreat` 和夜间 `dim_light` 上下文，已有被动通过正式检定生效；这不代表增加灯油、照明传播或新的灯具生产链。

## 拒绝后的协商

邻聚落的送粮请求仍需从实际家庭粮柜观察产生并通过同地点交谈传播。留粮约定可以拒绝整批援助，拒绝不扣钱、也不创造粮食。

开启协商的新世界中，拒绝者形成有来源的答复：本地需要留粮，可以重新商量至多两份。答复不会自动进入请求者的知识；必须实际传到对方面前。请求者仍缺粮时，才能根据已听到且未过期的答复形成减量请求，并把请求再传回来。

传回答复是普通成年居民也能选择的活动，不要求担任组织代表或先产生孤独需求。往返只使用消息里实际告知的地点，不读取对方当前隐藏位置；会占用行程和社交时间，也可能扑空、错过、被更紧迫的生存需求压过或超时。

捐助者只在知道这份减量请求、答复未过期、收货对象与数量相符、仍有真实余粮且路线可达时恢复合作。自家储备、既有运单、真实钱款和承运能力仍会阻止发货。之后复用原送粮合同、实际旅行、入柜和取食链，不以一条“愿意帮忙”记录替代交付。原生恢复核对双方消息、政策、数量、时效和运单来源。当前只是有限减量协商，不是任意谈判、长期外交条约或经济定价博弈。

## 谋生与危险

新版本允许比较多个符合知识与距离限制的公用采食地点；邻地选择仍需要真实收到的供给见闻。极饿时不必先耗尽所有钱才考虑采食，生产者也不再因为职业是农人或渔人而被永久禁止买饭。

有工具、有资源的食物生产者优先考虑用正规作业满足自己及已知家庭需求；缺工具或材料时仍可改为低产量徒手采食。已有生产进度、疲劳、路程、家人需要和亲见危险共同参与选择。生存优先级不免除原材料或工具限制。

危险区原先由按时出现的固定威胁长期占据，没有自身觅食需求。新规则给现有田边威胁增加一个最小资源反馈：累计六个活动小时后，若当地同一资源库有匹配的食物/根茎采集资源，消耗 0.5 单位并退开休息十八小时。资源不足不能免费获得饱足和离场；人物仍可能遭遇它、受伤或主动驱退它。

这是对抽象可采资源的竞争，不是吞吃 ItemStore 中别人的现成口粮，也不把耕地数值解释为真实土壤营养。资源事务核对生物类型、显式食谱、所在地点、食源标签、数量和觅食事实。完整生态、繁殖、捕食网和栖地移动仍未实现。

## 验收与边界

- 受控反例分别验证装备生产、付款、缺钱、卖家不在场、维修上限、夜间被动、消息往返与过期；一律称为测试注入。
- 至少三个种子、其中一个保留初始条件，运行三十个自然日并做机制关闭对照。记录每个人的进食、极饿、伤势、后续劳动，不只看总事实数。
- 装备验收追踪自然生产/购买到实际穿戴、使用和磨损的同一实例；绳具补给交易不能冒充战斗装备购买。
- 协商验收区分本地形成答复、对方听到答复、反向请求和实际送达，缺一环就记未完成。
- 后台合法游玩、被动模拟、程序驱动 UI 渲染、独立人测分别报告。保留旧世界行为，验证原生续跑，并以实际 Windows 包的启动与协议测试闭合发布验证。

下一阶段默认推荐极高推理；只有需要同时改动存档格式、实体生命周期和跨系统权限等高耦合合同，才单独提出 Ultra，不静默修改模型设置。
