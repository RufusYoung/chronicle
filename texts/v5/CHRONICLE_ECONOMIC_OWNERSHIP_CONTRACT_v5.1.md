# Chronicle 资源权属与有预算交换合同

更新于 2026-09-03。对应执行计划 W1，状态为设计已明确、编码待开始。本文不代表经济系统已经实现。

## 1. 本轮证据

- `settlement_network_system.gd` 的货流同时扣减来源库存与运力、增加目的储备，但 `unit_price` 只是记录数值，没有付款人与收款人的货币转移。现有“成交价”措辞超出了实际结算能力，W1 首批改动必须纠正。
- `organization_response_system.gd` 通过 `resource_stock_ids` 查找可调度库存。这证明组织与物资有关联，不证明组织拥有库存或取得了所有者许可。
- `npc_livelihood_system.gd` 把职业产物生成到劳动者持有的物品实例中。车夫和守夜人的职业定义把铜币列为产物，尚无实际雇主付款。
- 新制绳产业已消耗纤维并产出真实绳索，但需求来自近期货运次数。绳索没有真实买方、订单或损耗，长期积累也不会反过来抑制生产。
- 现有 `MarketService.execute_trade()` 已能原子化转移商品与铜币并写入 Exchange。这个能力应复用，不新建与 ItemStore 冲突的账户余额。

这些是系统缺口，不靠增加任务说明或手写商团故事解决。

## 2. 真值边界

| 对象 | 唯一真值 | 约束 |
| --- | --- | --- |
| 自然资源和道路运力 | ResourceStockStore | 鱼群恢复、地力与日运力是生产约束，不是可直接交付给买方的成品。 |
| 已生产的货物、工具和铜币 | ItemStore 的实例及 holder | 背包、组织金库和作坊库存都是按持有人查询的视图，不另存一份数量或余额。 |
| 资源使用权 | 资源记录的明确权利字段及来源事实 | `settlement_id` 只表示属地，不能隐含任意当地组织可免费扣取。 |
| 采购承诺与履约状态 | ExchangeStore | 订单只引用货物、双方、用途和来源，不复制实际库存。 |
| 当前预算规则 | 组织或聚落实体的 State | 可以存支出上限和必要储备，实际可用金额必须从所持铜币扣除有效承诺后派生。 |
| 发生过的交换、授权和违约 | Fact 与 Chronicle | 记录来源、双方、数量、原因和世界时间，不能被当前持有人变化改写。 |

自然资源可由聚落共同管理，不强制全部私有化。但共同管理必须有明确使用规则、可用额度和承载约束。组织在岗人数只影响协调能力，不自动授予财产权。

生成期可以按世界初始条件赋予有限物资和铜币，必须留下初始化来源。运行期组织成立只能取得实际拨款、会费或捐赠转入；解散后再成立不能刷新一份金库。自然恢复也不能恢复铜币或成品储备。

现有 `trade_reserve` 含聚合数量和小数，与离散 ItemInstance 并非同一种单位。不得简单把这个数再复制进 ItemStore。接入有偿成品货运前，逐类明确单位、转换来源、旧档兼容与移除旧扣减入口，保证没有双份供给或双重消费。

## 3. 编码顺序

### W1-A 权利与资金边界

先为自然资源使用与组织调度增加可验证授权，区分属地、管理者和实际成品持有人。生产、建造、组织调拨与网络货流都经过同一权利检查，未迁移旧世界采用明确的旧规则版本，不能在载入时偷偷夺取人物物品。

金库使用组织持有的铜币实例。所有拨款都同时减少来源持有量并增加目标持有量；人物死亡或组织退场时，未结承诺与剩余物资必须按已声明规则处理。余额不足时保留失败原因，不允许负余额、自动补币或从无关居民背包取款。

先纠正当前货流“成交价”和服务职业“领取薪酬”的呈现：未接入付款的路径明确标为旧版调拨或未接入预算的薪酬模型，不作为已实现经济的证据。

### W1-B 本地真实采购

先以制绳产物建立最小采购合同。买方必须是实际实体，需求必须对应计划执行的生产、道路维护或运输用途，不能只因另一个地点出现过货流而无限购买。

卖方从实际持有绳索的生产者中选择，读取其可售库存和最低自留量。买方比较用途、缺口、价格、支出上限和可支付铜币。同一报价与双方库存必须在提交前复核；陈旧报价、卖方失去物品、买方退场或资金被其他订单占用时拒绝结算。

采购在一笔现有事务中转移绳索和铜币、关闭订单、写入物品履历与事实。先实现本地现货整单成交，不先加部分成交、信用或投机。不能只写“采购完成”事实却不移动物品。

### W1-C 使用、支出和货运守恒

实际维护或运输使用买来的绳索，并按明确用途消耗数量；只购买、不使用不能让需求不断再生。无绳索时改变可执行服务或维护效果，不伪造已完成的工作。

服务职业必须有实际付款者或明确无偿劳动规则。铜币不再列为普通生产配方产物，工资不足会保留欠付或停止雇用的实际状态，不能继续生成薪酬。

跨镇货流逐类转为有持有人的成品交付，购买付款与运输消耗分开说明，但必须在统一事务边界内保持守恒。没有道路、运输能力或可交付成品时不能只扣钱并宣称到货。聚落救济可以无偿，但必须是有授权、有来源的转移，不能冒充市场成交。

### W1-D 产业反馈

制绳产业的新增、扩产和退出读有预算的未满足订单、实际成交、库存积压与持续净收支。无预算愿望不能与有效订单等权；无买方、无消耗或入不敷出的反事实不能继续被货运次数撑成永久繁荣。

产业成立仍须满足实际经验、资源、建材和地块条件。新经济规则改变的是判断依据，不跳过 G5-C2 已建立的成立、就业、生产、遗址和存档合同。

只有 W1-A 至 W1-D 均验收后，才把 W1 标为完成。先做通本地绳索采购不代表整个经济或跨镇贸易已完成。

## 4. 验收矩阵

| 验证 | 通过条件 |
| --- | --- |
| 权属 | 无授权组织不能消耗他方库存；合法共同资源使用扣取真实额度并保留来源。 |
| 资金 | 固定初始世界内，采购、工资、会费与组织重建不能改变铜币总量；明确损耗或外部发行必须单独有事实，不能藏在职业生产中。 |
| 原子性 | 测试注入未知物品、报价变化、资金不足或引用损坏时，付款、交货、订单和事实全部不发生。 |
| 双重支出 | 同一小时多个组织或订单争用相同库存、铜币和运力，只有实际可负担的结算成功。 |
| 消费 | 采购不等于使用；只有真实用途完成才消耗绳索，不能同一批货在 Item 与聚合储备重复消费。 |
| 生命周期 | 发起者死亡、组织解散与作坊退场后，不留下无人负责的有效订单；历史和财产去向仍可追溯。 |
| 产业反事实 | 相同种子与时间下，有资金与无资金、有消耗与无消耗、有原料与无原料产生可解释的成立、停产或退出差异。 |
| 存档 | 保存与载入后资金、物品、授权和未结承诺一致；重复推进或重载不能重复扣款、交货或刷新金库。 |
| 长期运行 | 至少三种子三十日，无负资产、悬空权属、失败事务与未解释的货币增发；报告产业分化与未发生的路径，不为凑事件修改阈值。 |
| 前台 | 执行前说明费用、用途和后果，执行后说明付款者、收款者、交付数量与失败原因；翻页和查看信息不推进世界时间。 |

受控缺钱、缺料和解散路径统一标为“测试注入”或“模拟干预”。自然长测与真实 UI 操作分别记录，不互相冒充。

## 5. 本阶段不做

暂不实现银行、借贷利息、任意拍卖、股票、复杂税制和全量产业平衡。初始价格可继续按基础价值与真实缺口计算，但必须说明价格依据，且价格必须成为实际支付约束。

W2 之后才处理封锁、争夺、让步和利益集团冲突。届时冲突应争夺本合同已经存在的资源使用权、预算或实际货物，而不只增加“敌对”标签。

默认生成世界试玩入口属于 R1，三十日前台响应属于 D1，保持独立验收。它们没有实现前，不能把本合同的模拟验证写成 Steam Demo 已可体验。
