# 共享身体代价合同

2026-09-21，RF6 的身体、劳动、危险与自救整合。既有 StateStore、事务和原生存档仍是真值，不新增生命、库存或计时 Store。

## 版本与取舍

- 新世界显式 `body_rules_version=1`；后台组合 `world_body_v1` 启用沿岸内容 v2 和身体 v1。RF1-RF5 修补后的 UI 沿岸整合与 `world_integration_v1` 在此基础上另加装备、协商与谋生规则，见整合合同。`world_body_v1`、`world_content_v2` 及旧存档维持各自原规则。
- bootstrap 固化六小时极饿间隔、每次健康损耗 2、饥饿损耗下限 40、每轮完成作业额外疲劳 2、进攻/防守减值 2。更改这些规则需要新版本，不能静默改旧世界。
- 初始 16 名居民与旅人共用规则。动态新生/迁入人物不在本次验收范围，不能声称全世代支持。
- 下限 40 是内部 Demo 的可逆工作假设，用于验证代价且保留自救，不代表最终死亡设计，也不会把低于 40 的战伤治回 40。永久死亡、器官损伤、完整营养与腐败尚未实现。

## 实际消费者

1. 饥饿 resolver 只累计真正极饿的小时，扣除餐食饱腹暂停和跨级前时间。余数 `hunger_strain_hours` 为 0–5 的整数，原生续跑保留。
2. 一次真实作业完成收取原疲劳 1，极饿时收取 3，上限仍是 10。采食产量、资源、工具和时间不豁免；没有把饥饿直接变成无法求生的禁令。
3. 现有危险交锋的进攻、防守读取相同减值；撤离不受本项减值。具体结果仍由能力、装备、骰点及威胁共同决定。
4. 进食消耗实际食品，缓解饥饿；下一普通时钟结算清除不再极饿的累计。进食本身不治疗健康，休养仍使用既有时间与补给规则。
5. 真实扣血提交 `actor_hunger_strain`，附人物、地点、时刻、健康前后值。本人损害优先进入等待/旅行结果，不得被前两条 NPC 消息挤掉；异地 NPC 的事实不自动成为玩家知识。

## 呈现与存档

- 选择前显示健康、饥饿、后续伤身时间和劳动/交锋减值；结果解释健康为何变化。内部计时与版本号不作为玩家结果逐行展示。
- 同一世界摘要不重复占据结果与决定依据。720p 路线每页两条、普通人物摘要三条；900p 恢复三条路线、四条人物。路线翻页和记录页保留完整信息，不推进时间，不新增嵌套滚动。危险对象摘要保留既有容量。
- 校验 bootstrap 编译身份、注册人物存在、版本一致与计时整数范围。旧存档不能仅插入状态字段而取得新规则。原生 JSON 的整数/浮点表示允许数值等价，不用 Dictionary 类型严格比较误拒有效旧精度。

## 验证边界

- 自然观察与合法后台游玩分别验证两种子三日、一个种子七日，以及两种子七日无人操作世界。
- 无粮、健康 40、极饿开局属于明确的测试注入；其后旅行、四小时采食、进食、休养均走正式接口。它证明该处境可自救，不证明任意贫困或任意危险地点都可自救。
- 同骰点交锋反例设置相同临界威胁，仅改变饥饿，必须实际提交成功/失败结果；不能在骰点不合适时静默跳过。
- 实际 Godot 渲染检查不等于独立人类试玩。七日结果不等于三十日生存、持续社会平衡或 RF6 全部通过。
