| M10 环境、魔物与危险 | RF5 已验收有限领地威胁、居民交锋与伤后生活；跨地巡游和生态尚缺。 | 有位置、动机和消退条件的威胁，作用于 NPC 与玩家；共用属性、装备、受伤和资源规则。当前退却为同一地块的状态，不做完整食物网。 |
| M11 战斗、装备与成长 | 槽位、修正器、特质/天赋/印记/技能已有；遭遇单次结算不等于完整战斗。 | 最小连续战斗状态，准备、攻守、脱离、伤势与战后恢复；被动用已有条件修正机制，实际经历触发有限成长。RF5/RF6，不照搬另一游戏全量数值。 |

共用骨架为：**对象与已知状态 → 可做的动作/作业 → 个体或组织选择 → 时间与实物占用 → 原事务提交 → 他人观察与反应 → 新候选**。记录系统从已提交结果生成纪事，不代替结果；有限随机性决定合格候选与遭遇变化，不承担编写整条故事的职责。

### 哪一轮算出现涌现

**RF3/RF4 已分别验收 E1 和 E2 的有限范围；RF6 玩家可感知的涌现仍未完成。** 这三个是有明确失败条件的工程目标，不是“堆够机制自动产生涌现”的承诺。已有基础生计存在局部状态驱动反应，未被抹去；E1/E2 的组合证据不替代 E3 或真实玩家体验。

- **E1，RF3：局部涌现。** 同一套机制在至少三种不同初始处境下产生至少两种不同因果结构，例如选择维修并继续供货、改做替代作业，或因实际成本拒绝交易。一次变化跨越至少三个机制族、两个自主人物，且后续决策读取变化；不能由姓名、固定日期、剧情阶段或试验脚本指定动作序列。先冻结三个七日自然样本，再做同源关闭一个关键机制的对照。自然样本与测试注入分别报告，不要求每个种子必有危机。
- **E2，RF4：有限活世界。** 三种子三十日，无代理行动、真实物流、两聚落/两利益者；至少出现两种不同的跨主体传导路径，并包含改变规则、拒绝或绕行后反馈到生活的样本。检查处于平静/失败状态的人，不强迫大家同方向变好。原生续跑一致，保持钱物来源；至少一种子在冻结规则后新增，不能所有种子都参与调参。
- **E3，RF6：可参与的涌现。** 从同一存档分支，在同一绝对时间比较旁观与三种合法行动策略，至少两种策略改变其他人物的资源、处境或下一选择；玩家能从现场和消息理解影响。程序记录通过不等于人测通过，RF7 继续验证取舍是否可理解且有吸引力。

例子仅说明因果形状：工具损坏使作业变慢，工匠在自己的订单与邻人的求助之间选择，延迟供货影响另一家的生活，对方改变合作态度，随后影响下一次借用。实现的是损坏、需求、可支付作业、知识与关系规则；**不编写“第几天工匠必须坏工具、拒绝谁、然后和解”的故事脚本**。

### 框架何时进入以扩内容为主

RF1 做第一次扩展试验，RF3 再验证跨用途，RF6 才验收参赛范围的内容扩展边界。冻结运行时代码后，仅增加/调整经过校验的数据，完成：

1. 两种有实际差异的食品进入已有采收/加工、储存、交易、消费链，不增加食品 ID 白名单。
2. 两种已有能力组合的工具/装备及一份替代材料配方，改变效率、消耗或风险，自动进入使用、维修、报价与 AI 候选。
3. 两种 NPC 处境/性情配置和一种魔物行为配置，使用已有决策能力；不能用姓名、职业专名或魔物 ID 在代码里分支。
4. 两个短插曲定义，只组合已支持的条件、结果与呈现，不借文本生成隐藏物资或必须完成的任务链。
5. 新定义经正式新世界、AI 合法入口、实际 UI 和原生存档验证；旧世界维持原规则。非法引用、无消费者的用途、无实现的效果和无条件正反馈必须被校验或集成测试暴露。

全部通过，才能说“**这个机制范围内可以主要堆内容**”。新增飞行、液体传播、肢体断裂、夺舍、继承法或全新装备触发语义，仍是机制开发，不会因为支持 JSON 就自动免费。NPC 数量也受运行成本与交互质量限制。大陆级政治、世代演变、深层生态和完整魔法属于长期 B 阶段，不谎称 Demo 框架已经覆盖。

### 执行成本与停止条件

- 不重新实现 Stores/Effects/Transactions/SaveEnvelope，不为了统一所有旧切片而先整体重构。先让两个用途共用现有接口，证明第三个能纯数据扩展，再推广；旧规则按 bootstrap 版本隔离，旧切片只保留兼容和回归。
- 每轮优先交出可运行的组合，再打磨。开发中用针对性合同、24 小时短跑与一个判别反例；候选稳定后跑七日；三十日广泛验证集中在 RF4/RF7，资源/存档核心改变或已知长期故障时提前跑相关长测。不能把短跑通过写成长期通过。
- 完整回归与 Windows 实包检查保留在冻结的运行时交付点，不为每个参数候选重复导出和执行全套。若改动共享 Store、事务或存档，按影响范围扩大回归；一次失败先运行失败项及相邻合同，修完后再跑冻结全套。每次交付的运行时仍须配匹配的新包与实际进程冒烟。

## 调整结论

### 人物基础要素（2026-09-06 追加）

用户建议参考矮人要塞的需求、性情、关系和记忆颗粒度。采用可组合且改变行为的要素，不以词条数量作为智能或涌现门槛。先用已有 StateStore、RelationshipStore、MemoryStore 接通家庭供给：当面得知缺粮，依据关系和出行容忍度，用本人钱采购并实际带回。详见[家庭供给合同](CHRONICLE_HOUSEHOLD_PROVISIONING_CONTRACT_v5.1.md)。新增需求须有真实满足方式、放弃代价及对他人的反馈，合并进 B3，不另开人格系统排期。

### 持续执行授权（2026-09-05 追加）

用户明确要求逐轮持续推进，完成一轮、提交代码或更新报告只是检查点，不自动结束任务。只有需要用户作实质决策、没有可继续的授权工作、用户暂停，或达到足以汇报的质变/关键成果节点时停下。常规实现方案、可逆数值和实验方法由 Agent 自行判断并记录。执行入口见根目录 `AGENTS.md`，项目 Skill 见 `.agents/skills/chronicle-world-development/SKILL.md`。

2026-09-06 用户进一步澄清：单个机制及其测试、打包不算关键节点，前轮仓储转运应只是中间检查点。阶段性节点要求多个系统合在一起运行并达到当前阶段的可观察结果；失败实验继续诊断和替换方法，不再据此结束。当前以需求、劳动、实物、出行、报酬和后续反应接成多日自主链，并通过反例与存档续跑，作为阶段汇报的最低前提。

撤销上一轮把开局生存基线当作用户阻塞项的处理。当前采用可逆工作假设：先验证有限资源下可以维持基本谋生，再用真实扰动检验危机；饥荒开局保留为待验证变体，不宣布为最终难度设计。保持饥饿、物资和货币约束，不用无限补给迎合通过率。

### 原设定回接（2026-09-05 追加）

用户要求先沿用最早的大世界、历史、地区与势力骨架。已核查原始六区设定与编年史，来源和争议见 [原设定衔接合同](CHRONICLE_CANON_WORLD_FOUNDATION_v5.1.md)。正式新世界现从镜湖北岸的回音港周边启动，生成两处小聚落与 16 名居民；大世界目录收录六界域和 17 个势力，但远方与国家政治尚未运行。湖湾镇、第七哨站和合成三镇保留回归，不自动成为正式地理。

这是 H2 的世界起点前置修正，取代“继续把合成三镇扩成正式世界”的方法，不取消既有合同。精确人口、资源和道路时间是实现参数；历史锚点与文明利益来自旧稿。文明之间的粮食、金属工具、情报与许可关系为后续 B2/B4 选择场景提供约束，不再凭空发明无关城市和组织。

世界单调的主要问题还没有解决。已有实体、事务、物品、关系、聚落和组织合同，但它们尚未共同支撑一个足以持续改变人物生活的世界。重复职责和按固定次序开放的地点不能继续作为开发主轴；也不能靠更丰富的文字把相同结算包装成涌现。

开发改为从世界底层相互作用向上推进。先证明世界在没有代理行动时可以持续运转，再让人物根据自己的处境行动，继而让聚落与组织共享资源约束、协作与摩擦，最后接入正式玩家人生。这里的“最后”以有限范围的世界验收为界，不以实现整部《矮人要塞》为前提。用户随后追加了 10 月 5 日前的参赛目标，因此本轮采用下文的限期范围；不得以完整实现 B1 至 B6 为由推迟可玩版本。

保留既有 Stores、统一 Effects、Transactions、物品身份与原生 SaveEnvelope。已经通过的资源权限、有限金库、绳索用途和磨损合同不推翻；暂不再扩写手写服役年份、固定路线节点和奖励模板。

## 第一轮世界范围

以原设定镜湖北岸的回音港为地理锚点，在港外有限范围生成地方聚落与生计。首轮不要求大陆地形随机，不要求每个组织或角色都无人工设定。保留主干历史与初始文明，要求生成角色和组织进入相同真值系统。准确地理未确定的远方不捏造坐标，静态背景不冒充自主运行。

当前生成夹具仍有一个被动旅人实体，供会话定位；B0 的世界模式禁止操作它。不能因此声称“完全无玩家实体的纯世界启动”已经完成。移除这项结构依赖归 B1，正式加入有目标的玩家归 B7。

每一层都必须回答：谁在什么地方，拥有什么，缺少什么，能知道什么，付出了什么，因而改变了谁的可选行动。地图、组织列表、随机姓名和事实数量都不能替代这些答案。

## 验收纪律

1. 分开报告无人干预模拟、代理通过合法接口游玩、真实 UI 输入和测试注入。AI 接口不接收任意 effects、强制骰点、隐藏状态写入或远程 NPC 指令。
2. 每个新增机制至少保留一条来源到后果的因果链及一个反例。例如没钱不成交、没有作业不磨损、道路不可达不能搬货。
3. 多种子差异比较实际人物、动作、资源与后果，不能只比较名字、随机种子、日志编号或文本。
4. 开放世界的自主运行不能以“日志一直增加”验收。记录工作与需求是否有变化、行动重复的原因、无法行动的人和逐渐耗尽的资源。
5. 任何完成度都说明量表和未覆盖范围。本轮不提高“矮人要塞式涌现”或“Steam Demo”百分比；控制入口和测试通过不直接改善这些体验指标。
6. 运行失败可能发生在行动已提交之后。必须返回明确的不确定状态，禁止自动重试造成第二次结算。
7. 明确数值精度合同。B0 发现原生存档会规范化资源比例的末位小数，尚未发现这一差异导致本轮整数资源或人物状态丢失；H1/B1 需区分内存重演、磁盘续跑和长时间阈值行为，不能把按原生精度一致写成浮点逐位一致。不要为通过测试偷偷改存档摘要或放宽所有行动比较。

## 创作约束

世界优先不意味着把 Chronicle 改为只有产业和财政的观察器。《矮人要塞》的因果世界是基础，《冒险生活》的短事件与装备选择、《来自深渊》的未知和代价、《奥德赛》的险途与归乡、《芙莉莲》的时间、关系与离别依然是最终体验目标。

B2 到 B5 为这些体验提供真实约束。B7 要验证玩家能因自己在乎的人、物资、目标和未知作出取舍，而非再出现一列“哪里亮了点哪里”的完成清单。
