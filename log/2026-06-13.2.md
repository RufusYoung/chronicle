## 六、第 2 阶段：世界状态数据结构

在 `world_sim_state.gd` 中定义最小世界状态。

至少包含以下数据结构：

### 1. WorldSimState

字段建议：

```gdscript
day: int
seed: int
regions: Dictionary
factions: Dictionary
world_facts: Array
world_news: Array
lead_candidates: Array
rng_state
```

### 2. RegionState

字段建议：

```gdscript
id: String
name: String
danger: float
order: float
scarcity: float
mystic: float
food: float
herbs: float
relics: float
information: float
beasts: float
population: float
owner_faction_id: String
tags: Array
recent_changes: Array
```

### 3. FactionState

字段建议：

```gdscript
id: String
name: String
power: float
wealth: float
food_need: float
hostility_to_player: float
relations: Dictionary
goal: String
known_facts: Array
active_region_id: String
```

### 4. WorldFact

用于记录真实发生过的世界事实，不只是文本日志。

字段建议：

```gdscript
id: String
day: int
type: String
region_id: String
faction_id: String
data: Dictionary
```

### 5. WorldNews

用于玩家可能听到的传闻或新闻。

字段建议：

```gdscript
id: String
day: int
region_id: String
source: String
summary: String
truth_level: float
related_fact_id: String
```

### 6. LeadCandidate

用于把世界状态投影为玩家能看见的线索。

字段必须包含：

```gdscript
id: String
day: int
type: String
region_id: String
source_faction_id: String
world_cause: String
urgency: float
freshness: float
risk: float
possible_actions: Array
projected_consequences: Dictionary
related_fact_id: String
```

重要要求：

`LeadCandidate` 不能凭空随机生成，必须有 `world_cause`。

## 七、第 3 阶段：最小世界种子

在 `data/world_seed_mirror_lake.json` 中建立最小世界。

必须包含 3 个地区：

```text
mirror_lake_forest
border_town
old_ruins
```

必须包含 3 个势力：

```text
wardens
smugglers
echo_cult
```

必须包含 4 类资源：

```text
food
herbs
relics
information
```

地区初始设计建议：

### mirror_lake_forest

* herbs 高
* beasts 中高
* mystic 中
* order 中
* danger 中

### border_town

* food 中
* information 中高
* order 高
* scarcity 中
* population 高

### old_ruins

* relics 高
* danger 高
* mystic 高
* population 低
* order 低

势力目标建议：

### wardens

维护秩序、压制走私者、阻止回声教团扩张。

### smugglers

获取财富和情报，利用匮乏，降低秩序。

### echo_cult

获取遗物与草药，提高 mystic，制造异象。

## 九、第 5 阶段：势力行动规则

每天每个势力应根据目标选择一个行动。

### wardens 行动类型

```text
patrol
suppress_smugglers
seal_ruins
escort_supplies
```

可能效果：

```text
order +
danger -
smugglers power -
scarcity -
```

### smugglers 行动类型

```text
raid_supplies
bribe_guards
spread_rumor
move_contraband
```

可能效果：

```text
wealth +
order -
scarcity +
information +
wardens relation -
```

### echo_cult 行动类型

```text
gather_relics
harvest_herbs
perform_ritual
spread_visions
```

可能效果：

```text
mystic +
relics -
herbs -
danger +
world_news 异象类 +
```

行动不需要复杂，但必须能改变世界。

## 十、第 6 阶段：线索投影

在 `world_to_leads_projector.gd` 中实现：

```gdscript
func generate_leads_from_world(state: WorldSimState) -> Array
```

线索类型至少包括：

```text
smoke
tracks
rumor
river
apparition
checkpoint
caravan
```

线索必须来自世界状态。

示例规则：

### 1. 匮乏导致商队袭击线索

条件：

```text
border_town.scarcity > 65
smugglers.power > 40
```

生成：

```text
type = caravan
world_cause = scarcity_high_and_smuggler_raid
possible_actions = investigate / protect / rob / ignore
```

### 2. mystic 过高导致异象线索

条件：

```text
old_ruins.mystic > 70
echo_cult.power > 35
```

生成：

```text
type = apparition
world_cause = cult_ritual_and_mystic_pressure
possible_actions = observe / interrupt / follow / report
```

### 3. order 过低导致烟柱线索

条件：

```text
mirror_lake_forest.order < 35
danger > 55
```

生成：

```text
type = smoke
world_cause = order_collapse_and_forest_conflict
possible_actions = approach / scout / avoid / inform_wardens
```

### 4. beasts 变化导致足迹线索

条件：

```text
mirror_lake_forest.beasts > 70
```

生成：

```text
type = tracks
world_cause = beast_migration
possible_actions = hunt / follow / set_trap / warn_travelers
```


```text

后续 smugglers hostility_to_player +
```

## 十二、第 8 阶段：无 UI 调试 Runner

在 `world_sim_debug_runner.gd` 中实现一个可以无头运行的调试脚本。

目标：

1. 使用固定 seed 加载 `world_seed_mirror_lake.json`。
2. 自动运行 30 天。
3. 打印每日摘要。
4. 打印最终地区状态。
5. 打印最终势力状态。
6. 打印所有 world_news。
7. 打印所有 lead_candidates。
8. 再做一次对比模拟：第 3 天插入玩家行为，然后运行到第 30 天。
9. 对比无玩家行为与有玩家行为的差异。

输出必须能看出：

```text
世界是否自己变化
势力是否采取行动
地区状态是否变化
线索是否由世界原因生成
玩家行为是否改变后续世界
```

## 十三、验收标准

本阶段完成后，必须满足：

### 1. 无玩家干预 30 天模拟

必须出现：

```text
至少 3 条 world_news
至少 5 条 lead_candidates
至少 1 个地区 tag 变化
至少 1 个势力 power / wealth / hostility 变化
至少 2 个地区的 danger / order / scarcity / mystic 发生明显变化
```

### 2. 有玩家干预对比模拟

同一 seed 下：

* A 组：无玩家干预跑 30 天
* B 组：第 3 天执行一个玩家行为后跑 30 天

第 10 天之后必须出现差异：

```text
world_news 不同
lead_candidates 不同
至少一个地区状态不同
至少一个势力状态不同
```

### 3. 线索必须有世界原因

所有 `LeadCandidate` 都必须有：

```text
world_cause
related_fact_id 或可解释的状态来源
```

如果线索只是随机生成，判定失败。

### 4. 不接 UI

本阶段不要求玩家能在主界面看到 world_sim 结果。

先让模拟核心独立跑通。
