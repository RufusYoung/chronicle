# 2026-06-23.3 指令：Raw Rule Effect Binding

## 任务性质

本次是 v5.1 世界模拟层的 raw rule 与 effect template 解耦任务。

上一轮已经完成：

```text
Raw Effect Template
↓
EffectTemplateResolver
↓
TransactionResolver
↓
TransactionResult
↓
TransactionWorldWriter
↓
Stores
```

并通过：

```text
[V5 SNAPSHOT TRANSACTION EFFECT TEMPLATE RESULT] PASS
[V5 RAW RULE PROTOTYPE RESULT] PASS
[V5 TRANSACTION STATE MEMORY RESULT] PASS
[V5 RELATIONSHIP TRACE RUMOR NARRATIVE RESULT] PASS
[V5 SIM RUNNER WORLD LOG RESULT] PASS
[V5 SIM SNAPSHOT CANDIDATE CONTEXT RESULT] PASS
```

但当前仍有一个结构问题：

```text
rule_id -> effect_template_id 的映射仍在 TransactionResolver 内部。
```

这意味着：

```text
新增一种 action rule 时，可能还要修改 TransactionResolver。
```

这不符合 Chronicle 的长期架构目标。

本次目标是：

```text
让 action rule 在 raw JSON 中声明 effect_template_id。
TransactionResolver 只读取候选行动上的 effect_template_id。
以后新增行动时，优先通过 raw rule + effect template 完成，不改 Resolver。
```

本次不要接 UI。
不要修改 rebuild 原型。
不要实现完整世界 Tick。
不要实现完整传闻传播。
不要实现 AI 文本。
不要实现湖湾镇完整闭环。
不要实现第七哨站长期项目。
不要把世界实体做成 Godot Node。
不要把世界状态写入 Godot 场景树。

---

## 0. 设计原则

本次继续遵守“细胞—组织—规则—系统”的结构。

### 0.1 Effect Atom：细胞

事务结果的最小效果单元：

```text
fact_added
state_change
relationship_change
memory_added
trace_added
rumor_added
narrative_result
```

### 0.2 Effect Template：组织

多个 effect atoms 组合成事务效果模板：

```text
give_food_help_effect
inquiry_concealed_item_effect
discipline_report_effect
discipline_conceal_effect
read_object_effect
inspect_trace_effect
```

### 0.3 Action Rule：规则

每条 action rule 应声明：

```text
这个行动在执行后使用哪个 effect template。
```

例如：

```json
{
  "rule_id": "give_food_to_hungry_person",
  "effect_template_id": "give_food_help_effect"
}
```

### 0.4 TransactionResolver：系统

`TransactionResolver` 不应认识每个具体 rule。

它只负责：

```text
读取 ActionCandidate
读取 SimSnapshot
读取 candidate.effect_template_id
调用 EffectTemplateResolver
返回 TransactionResult
```

禁止在 Resolver 中继续扩大：

```text
if rule_id == "..."
```

允许保留兼容 fallback，但必须标记为 legacy，并且测试要证明新规则不需要修改 Resolver。

# 检查点 3：TransactionResolver 不再维护主要映射表

## 3.1 修改 TransactionResolver

修改：

```text
chronicle-godot/scripts/sim/transaction/transaction_resolver.gd
```

要求：

```text
resolve_action(candidate, context_or_snapshot) -> TransactionResult
```

新流程：

```text
1. 读取 candidate.effect_template_id。
2. 如果存在，调用 EffectTemplateResolver.resolve_template(effect_template_id, candidate, snapshot)。
3. 返回 TransactionResult。
```

不再以内部硬编码映射作为主要路径。

---

## 3.2 Legacy fallback

可以保留兼容 fallback：

```text
candidate.effect_template_id 为空时，根据 rule_id 尝试 legacy 映射。
```

但必须满足：

```text
1. fallback 只用于旧测试或旧数据兼容。
2. 新测试必须证明使用 raw rule effect_template_id 时不会走 fallback。
3. 报告中必须写明 legacy fallback 只是过渡机制。
```

理想情况下，已有测试都应走 raw 绑定，不再走 legacy。

---

## 3.3 Resolver 不允许地点 / 人物特判

禁止：

```gdscript
if target_id == "recruit_elai":
if location_id == "outpost_kitchen":
if entity_id == "chen_mi":
```

允许：

```text
读取 candidate.effect_template_id。
读取 snapshot。
读取 tags / roles。
交给 EffectTemplateResolver 绑定变量。
```
