
上一轮只完成了：

```text

记录 obligation
记录 exchange
记录 deferred consequence
```

但还没有：

```text
履行 obligation
违约 obligation
结算 exchange
触发 deferred consequence
让 pressure 对候选生成产生最小影响
```

本次目标不是完整 World Tick。
本次不做自动日程推进、不做 NPC 自主行动、不做完整时间系统。

本次只做一件事：

```text
证明已经埋下的 obligation / exchange / deferred consequence / pressure
可以被手动触发、结算，并再次写回世界。
```

目标链路：

```text
前序行动产生 obligation / exchange / deferred consequence / pressure
↓
SimSnapshot 读取当前结构
↓
ConsequenceTriggerSystem 手动触发
↓
生成 TransactionResult
↓
TransactionWorldWriter 写回 Store
↓
WorldLog 记录 resolution
↓
下一次 Snapshot 可读到更新后的状态
```

本次不要接 UI。
不要修改 rebuild 原型。
不要实现完整世界 Tick。
不要实现完整传闻传播。
不要实现 AI 文本。
不要实现湖湾镇完整闭环。
不要实现第七哨站长期项目。
不要把世界实体做成 Godot Node。
不要把世界状态写入 Godot 场景树。

## 0. 设计原则

### 0.1 本次不是自动世界推进

禁止：

```text
每天自动 tick
全世界 NPC 自动行动
自动推进所有地点
自动结算所有义务
自动触发所有后果
```

正确方向：

```text
手动调用 trigger_key
手动指定 obligation_id
手动指定 exchange_id
用测试证明结构能触发和结算
```

也就是说，本次是 World Tick 之前的基础触发器。

---

### 0.2 后果触发也是事务

触发和结算不应直接改 Store。

正确链路：

```text
ConsequenceTriggerSystem
↓
TransactionResult
↓
TransactionWorldWriter
↓
Stores
```

禁止：

```gdscript
obligation_store._obligations[id].status = "fulfilled"
```

应该通过：

```text
TransactionResult.obligation_updates
TransactionWorldWriter.apply_result()
ObligationStore.apply_obligation_update()
```

---

### 0.3 新增的是通用结构，不是第七哨站硬编码

禁止：

```text
if rule_id == "trade_watch_duty_for_silence":
    recruit_elai 履行值夜
```

正确方向：

```text
任何 open obligation
都可以被 fulfill / breach

任何 open exchange
都可以被 settle / fail

任何 pending deferred consequence
都可以按 trigger_key 触发
```

第七哨站只是测试切片，不是系统特判。

# 检查点 5：新增 ConsequenceTriggerSystem

## 5.1 新增目录和脚本

新增：

```text
chronicle-godot/scripts/sim/consequence/consequence_trigger_system.gd
```

职责：

```text
读取 SimSnapshot 中的 obligation / exchange / deferred consequence。
按手动输入触发 settlement。
返回 TransactionResult。
```

最小接口：

```text
fulfill_obligation(snapshot, obligation_id: String) -> TransactionResult
breach_obligation(snapshot, obligation_id: String) -> TransactionResult
settle_exchange(snapshot, exchange_id: String) -> TransactionResult
trigger_deferred_by_key(snapshot, trigger_key: String) -> Array
trigger_deferred(snapshot, deferred_id: String) -> TransactionResult
```

`trigger_deferred_by_key` 返回多个 TransactionResult，因为同一个 trigger_key 可能对应多个 pending consequence。

---

## 5.2 模板选择

默认使用：

```text
fulfill_obligation -> obligation_fulfilled_effect
breach_obligation -> obligation_breached_effect
settle_exchange -> exchange_settled_effect
trigger_deferred -> deferred_consequence_triggered_effect
```

如果 record 中存在：

```text
fulfill_template_id
breach_template_id
settle_template_id
trigger_template_id
```

则优先使用 record 中的模板。

这保证以后可以扩展不同类型义务 / 交换 / 后果的结算方式。

---

## 5.3 变量绑定

ConsequenceTriggerSystem 需要给 EffectTemplateResolver 传入 bindings：

```text
actor_id
target_id
location_id
rule_id
obligation_id
exchange_id
deferred_id
trigger_key
```

建议规则：

```text
obligation:
actor_id = owner_id
target_id = target_id

exchange:
actor_id = party_a
target_id = party_b

deferred consequence:
actor_id = source_actor_id 或 player
target_id = target_id 或空
trigger_key = trigger_key
```

如果字段缺失，用安全默认值，不崩溃。

---

## 5.4 不直接写 Store

ConsequenceTriggerSystem 只返回 TransactionResult。

禁止：

```gdscript
obligation_store.mark_fulfilled(...)
```

写入仍由：

```text
TransactionWorldWriter
```

完成。

# 检查点 6：Pressure 影响候选优先级

## 6.1 修改 ActionAffordanceSystem

修改：

```text
chronicle-godot/scripts/sim/action/action_affordance_system.gd
```

新增最小 pressure priority 支持。

raw rule 可以声明：

```json
"pressure_priority": [
  {
    "scope_id": "seventh_outpost",
    "pressure_type": "unresolved_issue",
    "threshold": 10,
    "priority_delta": 20
  }
]
```

生成候选时，如果输入是 SimSnapshot，且 snapshot 中对应压力值达到 threshold，则：

```text
candidate.priority += priority_delta
candidate.extra.pressure_priority_applied = true
```

如果当前 ActionCandidate 没有 extra 字段，可以以最小方式增加。

不要让 pressure 直接决定事务结果。
这里只影响候选优先级。

---
