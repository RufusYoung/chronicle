# 2026-06-23.5 指令：Candidate-only Effect Template Batch 1

## 任务性质

本次是 v5.1 世界模拟层的 candidate-only 规则写回扩展任务。

上一轮已经完成：

```text
Raw Rule transaction_mode
↓
ActionCandidate transaction_mode + effect_template_id
↓
TransactionResolver 按契约执行
↓
TransactionResult 记录 contract_status
↓
SimRunner / SimWorldLog 记录和统计契约状态
```

并通过：

```text
[V5 TRANSACTION CONTRACT CLEANUP RESULT] PASS
[V5 RAW RULE PROTOTYPE RESULT] PASS
[V5 TRANSACTION STATE MEMORY RESULT] PASS
[V5 RELATIONSHIP TRACE RUMOR NARRATIVE RESULT] PASS
[V5 SIM RUNNER WORLD LOG RESULT] PASS
[V5 SIM SNAPSHOT CANDIDATE CONTEXT RESULT] PASS
[V5 SNAPSHOT TRANSACTION EFFECT TEMPLATE RESULT] PASS
[V5 RAW RULE EFFECT BINDING RESULT] PASS
```

上一轮已经明确：

```text
candidate_only 是显式事务模式，不是错误。
effect_template 模式缺少 effect_template_id 会被视为 invalid_contract。
TransactionResolver 不再依靠 rule_id 猜 effect template。
```

本次不要把所有 candidate-only 规则都升级为写回规则。

本次只处理三条已经具备后续世界意义的规则：

```text
hear_rumor_seed
request_favor_from_indebted_person
ask_about_food_pressure_at_market
```

本次不处理：

```text
approach_visible_person
confirm_ration_record_with_cook
trade_watch_duty_for_silence
delay_military_issue_until_after_patrol
```

原因：

```text
approach_visible_person 更像交互入口，不一定应该写入世界历史。
confirm_ration_record_with_cook / trade_watch_duty_for_silence / delay_military_issue_until_after_patrol 需要更完整的军纪 / 交换 / 时间压力设计，本次先不碰。
```

本次目标不是扩剧情，而是验证：

```text
部分 candidate-only 规则
↓
新增 effect template
↓
raw rule 改为 transaction_mode: effect_template
↓
绑定 effect_template_id
↓
不修改 TransactionResolver
↓
执行后产生 Fact / Memory / Relationship / Narrative 等世界后果
```

本次不要接 UI。
不要修改 rebuild 原型。
不要实现完整世界 Tick。
不要实现完整传闻传播。
不要实现 AI 文本。
不要实现湖湾镇完整闭环。
不要实现第七哨站长期项目。
不要把世界实体做成 Godot Node。
不要把世界状态写入 Godot 场景树。

---

## 0. 设计原则

### 0.1 本次不是逐条硬写剧情

禁止：

```text
if rule_id == "hear_rumor_seed":
    专门写死某条传闻
```

正确方向：

```text
hear_rumor_seed 使用 hear_rumor_effect
request_favor_from_indebted_person 使用 request_favor_effect
ask_about_food_pressure_at_market 使用 ask_market_pressure_effect
```

也就是：

```text
Action Rule
↓
effect_template_id
↓
Effect Template
↓
EffectTemplateResolver
↓
TransactionResult
```

`TransactionResolver` 不应新增 rule_id 特判。

---

### 0.2 三条规则的定位

#### hear_rumor_seed

含义：

```text
玩家听见或得知一条已经存在的 rumor seed。
```

执行后应该产生：

```text
Fact：actor_heard_rumor_seed
Memory：actor remembers_heard_rumor
Narrative：玩家听见一条传闻
```

本次不要实现完整传闻传播。
不要删除 rumor seed。
不要实现传闻失真。
不要实现社会网络扩散。

---

#### request_favor_from_indebted_person

含义：

```text
玩家向一个欠自己人情、信任自己或感激自己的人请求帮忙。
```

执行后应该产生：

```text
Fact：actor_requested_favor_from_target
Relationship：target -> actor debt -5
Memory：target remembers_favor_requested
Narrative：玩家向对方提出请求
```

本次不要实现“帮忙是否成功”的复杂判定。
只做“请求发生了，并消耗一部分人情债”的最小写回。

---

#### ask_about_food_pressure_at_market

含义：

```text
玩家向市场相关人物打听粮食压力、粮价异常或供应紧张。
```

执行后应该产生：

```text
Fact：actor_asked_about_market_pressure
Memory：actor learned_market_pressure
Narrative：玩家得知市场压力
```

本次不要实现完整经济系统。
不要生成新粮价。
不要改市场价格。
只记录“玩家得知了这个压力”。
