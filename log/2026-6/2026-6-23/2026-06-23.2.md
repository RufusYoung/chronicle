# 2026-06-23.2 指令：Snapshot Transaction Resolver + Effect Template Prototype

## 任务性质

本次是 v5.1 世界模拟层的事务解析重构任务。

上一轮已经完成：

```text
Fixture 初始状态
↓
SimContext
↓
Stores
↓
SimSnapshot
↓
ActionAffordanceSystem
↓
ActionCandidate
↓
Transaction
↓
WorldWriter 写回 Stores
↓
重新生成 SimSnapshot
↓
下一步候选行动读取当前世界状态
```

并通过：

```text
[V5 SIM SNAPSHOT CANDIDATE CONTEXT RESULT] PASS
[V5 RAW RULE PROTOTYPE RESULT] PASS
[V5 TRANSACTION STATE MEMORY RESULT] PASS
[V5 RELATIONSHIP TRACE RUMOR NARRATIVE RESULT] PASS
[V5 SIM RUNNER WORLD LOG RESULT] PASS
```

但当前仍有一个结构问题：

```text
ActionAffordanceSystem 已经开始读取 SimSnapshot，
但 TransactionResolver 仍主要读取 SimContext。
```

这会造成潜在不一致：

```text
候选行动来自当前世界快照，
但事务结果可能仍参考初始上下文。
```

本次目标不是给某条行动硬写结果。
本次目标是建立最小事务效果模板机制。

也就是说：

```text
不是专门给 ask_about_concealed_item 写一个结果。
而是建立 effect atoms + effect template，
让 ask_about_concealed_item 使用一个通用的 inquiry_concealed_item_effect 模板。
```

---

## 0. 设计原则

本次必须遵守“细胞—组织—器官—系统”的结构。

### 0.1 Effect Atom：细胞

事务效果的最小单位是 effect atom。

包括：

```text
fact_added
state_change
relationship_change
memory_added
trace_added
rumor_added
narrative_result
```

这些是事务写回的“细胞”。

### 0.2 Effect Template：组织

多个 effect atoms 组合成一个 effect template。

例如：

```text
give_food_help_effect
inquiry_concealed_item_effect
discipline_report_effect
discipline_conceal_effect
read_object_effect
inspect_trace_effect
```

这些是事务结果的“组织”。

### 0.3 Domain Rule：器官

不同领域使用不同模板：

```text
民间粮食危机可以用 give_food_help_effect。
军纪口粮问题可以用 discipline_report_effect。
询问隐藏物可以用 inquiry_concealed_item_effect。
```

### 0.4 Resolver / Writer：系统

`TransactionResolver` 负责：

```text
读取 ActionCandidate
读取 SimSnapshot
读取 effect template
生成 TransactionResult
```

`TransactionWorldWriter` 负责：

```text
把 TransactionResult 写入 Stores
```

禁止把事务结果直接写在 UI、场景节点或地点按钮里。

## 1.2 Effect Template 结构

每个模板至少包含：

```text
effect_template_id
description
facts
state_changes
relationship_changes
memories
traces
rumors
narrative
```

允许使用占位变量：

```text
actor_id
target_id
target_display_name
superior_id
superior_display_name
location_id
rule_id
```

示例结构：

```json
{
  "effect_template_id": "inquiry_concealed_item_effect",
  "description": "询问某人藏着什么时产生的最小事务结果。",
  "facts": [
    {
      "fact_type": "actor_asked_about_concealed_item",
      "actor_id": "{actor_id}",
      "target_id": "{target_id}",
      "location_id": "{location_id}"
    }
  ],
  "relationship_changes": [
    {
      "source_id": "{target_id}",
      "target_id": "{actor_id}",
      "axis": "fear",
      "delta": 5,
      "reason": "being_questioned_about_concealed_item"
    }
  ],
  "memories": [
    {
      "owner_id": "{target_id}",
      "memory_type": "being_questioned_about_hidden_item",
      "source_fact_type": "actor_asked_about_concealed_item",
      "emotional_tone": "uneasy",
      "clarity": "medium",
      "can_be_told_as_rumor": false
    }
  ],
  "narrative": {
    "summary": "对方意识到你注意到了他藏着的东西。"
  }
}
```

注意：

```text
这是 inquiry_concealed_item_effect 模板。
不是 recruit_elai 专属结果。
不是第七哨站专属结果。
不是地点按钮表。
```

# 检查点 2：EffectTemplateResolver

## 2.1 新增 EffectTemplateResolver

新增：

```text
chronicle-godot/scripts/sim/transaction/effect_template_resolver.gd
```

职责：

```text
读取 effect template。
将 ActionCandidate + SimSnapshot 中的当前对象、人物、地点、制度信息注入模板。
生成 TransactionResult 的各类 effect arrays。
```

最小接口：

```text
load_effect_templates(path: String)
get_template(template_id: String) -> Dictionary
resolve_template(template_id: String, candidate, snapshot) -> TransactionResult
```

如果已有 `SimRegistry` 更适合加载 JSON，可以复用 `SimRegistry`，但仍需要有清晰的模板解析入口。

---

## 2.2 变量绑定

Resolver 至少支持这些变量：

```text
{actor_id}
{target_id}
{target_display_name}
{location_id}
{rule_id}
{superior_id}
{superior_display_name}
```

变量来源：

```text
actor_id:
优先从 snapshot.player.id 读取。
没有时使用 "player"。

target_id:
从 candidate.target_id 读取。

target_display_name:
从 snapshot.get_entity(target_id).display_name 读取。
没有时使用 target_id。

location_id:
从 snapshot.location.id 读取。

rule_id:
从 candidate.rule_id 读取。

superior_id:
优先从 candidate.extra.superior_id 读取。
没有时从 snapshot 中查找 tags 包含 superior / captain 的 person。
没有时使用空字符串。

superior_display_name:
从 superior entity 读取。
没有时使用 superior_id。
```

不要写：

```text
if target_id == "recruit_elai"
if location_id == "outpost_kitchen"
```

允许根据 tags / roles 查询：

```text
entity.tags contains "captain"
entity.tags contains "superior"
```

---

## 2.3 State 降级操作

effect template 中 state change 需要支持：

```text
operation: "decrease_tier"
```

例如：

```json
{
  "entity_id": "{target_id}",
  "key": "hunger",
  "operation": "decrease_tier",
  "reason": "give_food_help_effect"
}
```

最终由 `StateStore.apply_state_change` 或 Resolver 转成：

```text
high -> medium
```

不要在模板里写死只适用于陈米。

---

## 2.4 Relationship clamp

effect template 里的 relationship change 仍然交给 `RelationshipStore` clamp。
Resolver 不需要自己 clamp，但要保持 axis / delta 正确。

# 检查点 4：SimRunner 使用 Snapshot 执行事务

## 4.1 修改 SimRunner

修改：

```text
chronicle-godot/scripts/sim/core/sim_runner.gd
```

当前候选生成已经使用 snapshot。
本次要求事务解析也使用同一个 step snapshot：

```text
step_snapshot = SimSnapshotBuilder.build_snapshot(context, stores)
candidates = ActionAffordanceSystem.generate_candidates(step_snapshot, rules)
candidate = select candidate
result = TransactionResolver.resolve_action(candidate, step_snapshot)
TransactionWorldWriter.apply_result(result, stores)
```

不要在 runner 中把 `context` 传给 resolver，除非是兼容 fallback。
