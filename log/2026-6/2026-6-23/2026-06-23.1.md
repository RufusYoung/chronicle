# 检查点 1：新增 SimSnapshot

## 1.1 新增 SimSnapshot

新增：

```text
chronicle-godot/scripts/sim/core/sim_snapshot.gd
```

职责：

```text
SimSnapshot 是某一时刻的当前世界读取视图。
它不拥有永久世界状态。
它从 SimContext + Stores 构建，用于候选行动生成、测试和调试。
```

它应包含：

```text
fixture_id
location
region_state
institution
player
entities
states
relationships
memories
traces
rumors
facts
```

最小接口：

```text
get_entity(entity_id: String) -> Dictionary
get_entities() -> Array
get_visible_entities() -> Array
get_entities_by_type(type: String) -> Array
get_entity_state(entity_id: String, key: String, default_value = null)
get_relation(source_id: String, target_id: String, axis: String, default_value = 0)
get_memories(owner_id: String) -> Array
get_visible_traces() -> Array
get_rumor_seeds() -> Array
get_facts() -> Array
get_location_tags() -> Array
get_region_state_value(key: String, default_value = null)
get_institution_value(key: String, default_value = null)
get_player_value(key: String, default_value = null)
```

注意：

```text
SimSnapshot 是只读视图。
不要在 SimSnapshot 里写入 Store。
不要让 SimSnapshot 直接执行事务。
```

---

## 1.2 新增 SimSnapshotBuilder

新增：

```text
chronicle-godot/scripts/sim/core/sim_snapshot_builder.gd
```

职责：

```text
从 SimContext 和当前 Stores 构建 SimSnapshot。
```

最小接口：

```text
build_snapshot(context: SimContext, stores: Dictionary) -> SimSnapshot
```

stores 可包含：

```text
fact_store
state_store
relationship_store
memory_store
trace_store
rumor_store
```

构建规则：

```text
1. 从 SimContext 读取 fixture 初始 entities / location / region_state / institution / player。
2. 用 StateStore 覆盖实体当前状态。
3. 用 RelationshipStore 注入当前关系。
4. 用 MemoryStore 注入当前记忆。
5. 用 TraceStore 注入当前痕迹。
6. 用 RumorStore 注入当前传闻种子。
7. 用 FactStore 注入当前事实。
```

如果某个 store 不存在，允许使用空数据。

## 2.2 饥饿行动改为读取当前状态

`give_food_to_hungry_person` 必须读取当前状态，而不是 fixture 初始状态。

规则第一版调整为：

```text
只有 hunger 为 high 或 extreme 时，才生成 give_food_to_hungry_person。
```

因此：

```text
陈米初始 hunger = high
↓
给食物后 hunger high -> medium
↓
后续 snapshot 中不应再为 chen_mi 生成 give_food_to_hungry_person
```

这一步是本任务最关键验证点。

不要通过 entity_id 特判实现。

禁止：

```gdscript
if entity_id == "chen_mi":
    skip give_food
```

正确：

```text
读取 snapshot.get_entity_state(target_id, "hunger")
判断 hunger 是否仍为 high / extreme
```


这不是完整 NPC 行为，只是证明 RelationshipStore 已经能参与候选生成。

# 检查点 3：SimRunner 改用 Snapshot

## 3.1 修改 SimRunner

修改：

```text
chronicle-godot/scripts/sim/core/sim_runner.gd
```

每一步执行前：

```text
1. 用 SimSnapshotBuilder 从当前 stores 构建 snapshot。
2. 把 snapshot 传给 ActionAffordanceSystem.generate_candidates。
3. 从 candidates 里按 scenario step 选择 action。
4. resolve transaction。
5. TransactionWorldWriter 写入 stores。
6. WorldLog 记录本步。
7. 下一步重新构建 snapshot。
```

不再只靠把 StateStore 写回 SimContext。

允许保留旧的 context state sync 作为兼容，但候选生成必须优先使用 snapshot。

---

## 3.2 Runner 返回 snapshot 摘要

`run_sequence` 返回值增加：

```text
snapshot_summary
```

至少包含：

```text
final_fact_count
final_trace_count
final_rumor_count
final_relationship_count
final_memory_count
```

也可以包含：

```text
final_candidate_probe
```

用于测试后续候选是否来自最新 snapshot。
