# 任务：项目清理、文档结构整理与冗余代码归档

## 一、任务背景

Chronicle 当前已经进入需要整理架构的阶段。

现状问题：

1. 当前 Demo 能运行，但项目中存在旧代码、旧文档、重复项目副本、未接入系统和占位内容。
2. 当前运行逻辑与已有的数据驱动框架、地区 JSON、旧世界模拟逻辑尚未合并。
3. 如果继续直接开发世界演化引擎，会在旧结构上继续堆复杂度。
4. 下一阶段开发 `world_sim_mvp` 前，必须先清理项目结构，建立清晰的文档与归档规则。

本任务不是开发新玩法，不是扩写事件，不是优化 UI。

本任务目标是：

> 在不破坏当前可运行 Demo 的前提下，完成项目引用审计、冗余代码归档、文档目录整理和项目结构说明，为后续世界演化引擎开发做准备。

---

## 二、最高原则

1. 不允许直接删除文件。
2. 必须先做引用审计，再移动归档。
3. 当前 Demo 必须保持可运行。
4. 不允许开始开发世界演化引擎。
5. 不允许扩写事件池。
6. 不允许继续优化“稳/赌/退”模板。
7. 不允许重构 UI。
8. 不允许修复或继续扩展旧 `world_generation.gd`。
9. 不允许把“未接入但未来可能有价值”的内容当垃圾删除。
10. 清理完成后必须输出报告。

---

## 三、重要保护目录与文件

以下内容禁止删除、禁止移动、禁止重命名，除非后续得到明确指令。

### 1. 当前 Demo 核心文件

```text
chronicle-godot/project.godot
chronicle-godot/scenes/ui/mainui.tscn
chronicle-godot/scenes/ui/story_player.gd
chronicle-godot/scripts/gen/world_generation_v03.gd
```

### 2. 当前 UI、字体、图片、脚本直接引用的资源

包括但不限于：

```text
chronicle-godot/assets/
chronicle-godot/scenes/
chronicle-godot/scripts/
```

需要先做引用审计，确认未引用后才允许归档。

### 3. 数据目录

```text
chronicle-godot/data/
```

`data/` 中的 JSON 很多虽然尚未接入当前 Demo，但后续可能用于世界演化引擎、地区数据、资源系统、事件链和生成器。

因此：

* 不要删除。
* 不要随意移动。
* 不要因为“当前 Demo 未加载”就判定为无用。
* 只能在报告中标记“已存在但未接入”。

### 4. 备用素材目录

```text
C:\code\game\chronicle\chronicle-godot\素材包
```

该目录不是无用素材。

这是后续可能使用的备用素材库。

规则：

* 禁止删除。
* 禁止移动。
* 禁止归档。
* 禁止重命名。
* 禁止因为当前未引用就判定为垃圾。
* 可以在项目结构说明中标记为“备用素材库，暂不参与清理”。

如需要，可以在该目录内新增一个说明文件：

```text
chronicle-godot/素材包/README.md
```

内容说明：

```markdown
# 素材包

本目录为 Chronicle 项目的备用素材库。

其中素材不一定已接入当前 Demo，但后续可能用于 UI、场景、角色、音效、演示版本或正式版本。

清理项目时禁止删除、移动或重命名本目录。
```

### 5. Godot 资源元文件

以下文件不要随意删除：

```text
*.import
*.uid
*.tres
*.res
```

尤其是 `.uid` 文件，不要作为垃圾文件清理。

只有当对应源资源已经确认归档，并且不会影响当前 Demo 时，才允许一并处理。

## 七、第三阶段：冗余代码归档规则

本阶段目标是清理冗余代码，而不是删除资产。

允许归档的内容包括：

1. 确认没有被当前 Demo 引用的旧实验脚本
2. 明显损坏、乱码、不能稳定运行的旧脚本
3. 嵌套旧项目副本
4. 重复的旧 Demo 脚本
5. 与当前入口无关、且已经被新版本替代的旧代码
6. 临时测试脚本
7. 明显废弃的旧文档

优先审计以下内容：

```text
chronicle-godot/chronicle/chronicle-godot
chronicle-godot/scripts/gen/world_generation.gd
chronicle-godot/scripts/gen/ 中未被引用的旧实验脚本
chronicle-godot/texts/ 中损坏或重复的旧文档
```

处理规则：

### 1. 嵌套旧项目副本

如果确认：

```text
chronicle-godot/chronicle/chronicle-godot
```

没有被当前项目引用，则移动到：

```text
chronicle-godot/_archive/legacy_project_copy/
```

不要删除。

### 2. 旧 `world_generation.gd`

如果确认：

```text
chronicle-godot/scripts/gen/world_generation.gd
```

不是当前 Demo 运行逻辑，并且存在乱码、换行损坏或不能稳定使用，则移动到：

```text
chronicle-godot/_archive/damaged_or_legacy_scripts/
```

如果不确定是否还有引用，则不要移动，只在报告中标记为：

```text
legacy-risk: 当前未接入，但暂不移动
```

### 3. 未接入但结构有价值的生成器

例如：

```text
Registry
RegionLoader
WeightedPick
ChainEngine
EventGenerator
RegionGenerator
ResourceGenerator
EquipmentGenerator
CreatureVariantGenerator
NpcInteractions
WorldState
RNG
```

这些不应直接当作垃圾。

规则：

* 如果文件正常、可读、结构清晰，保留原位。
* 如果文件损坏、乱码、重复，则归档。
* 如果只是“当前 Demo 未接入”，不要移动。
* 在报告中标记为“后续 world_sim_mvp 可参考或接入”。

### 4. 文档清理

旧文档不要平铺在 `texts/` 根目录。

可读、有长期价值的文档进入：

```text
chronicle-godot/texts/specs/
chronicle-godot/texts/plans/
chronicle-godot/texts/decisions/
```

损坏、重复、过期文档进入：

```text
chronicle-godot/texts/archive/
```

## 八、第四阶段：整理 `texts/` 文档结构

`log/` 和 `texts/` 分工如下：

```text
log/   = 每日指令和执行流水，一天一个 md 文件，由用户追加维护
texts/ = 长期文档、报告、规格、决策和阶段计划
```

不要移动 `log/`。

请将 `texts/` 整理为：

```text
chronicle-godot/texts/
  README.md

  reports/
    2026/

  specs/

  decisions/

  plans/

  archive/
    old_reports/
    old_specs/
    old_plans/
    damaged_docs/
```

### 1. reports

放任务完成后的结果报告。

命名规则：

```text
YYYY-MM-DD_task_name_report.md
```

示例：

```text
chronicle-godot/texts/reports/2026/2026-06-13_project_cleanup_report.md
chronicle-godot/texts/reports/2026/2026-06-14_world_sim_mvp_report.md
```

报告说明“发生过什么”。

### 2. specs

放长期系统规格。

示例：

```text
chronicle-godot/texts/specs/world_sim_mvp_spec.md
chronicle-godot/texts/specs/lead_system_spec.md
chronicle-godot/texts/specs/region_state_schema.md
chronicle-godot/texts/specs/faction_system_spec.md
```

规格说明“系统应该是什么”。

不要每天新建 spec。只有设计真的稳定或发生架构级变化时才更新。

### 3. decisions

放架构决策记录，采用 ADR 格式。

命名规则：

```text
ADR-0001-project-cleanup-before-world-sim.md
ADR-0002-world-sim-as-core-layer.md
ADR-0003-events-as-projection-layer.md
```

每个 ADR 至少包含：

```markdown
# ADR-000X：标题

## 状态
已采纳 / 暂定 / 废弃

## 背景
为什么需要这个决策。

## 决策
具体决定是什么。

## 后果
这个决定会带来什么影响。
```

请至少建立以下 ADR：

```text
chronicle-godot/texts/decisions/ADR-0001-project-cleanup-before-world-sim.md
chronicle-godot/texts/decisions/ADR-0002-world-sim-as-core-layer.md
chronicle-godot/texts/decisions/ADR-0003-events-as-projection-layer.md
```

ADR-0001 核心内容：

```text
在开发 world_sim_mvp 前，先清理项目结构、归档旧代码、整理文档索引，避免在混乱架构上继续堆功能。
```

ADR-0002 核心内容：

```text
Chronicle 的长期核心是自运行世界模拟层。地区、势力、资源、生态、传闻和线索的演化高于事件池扩写。
```

ADR-0003 核心内容：

```text
事件和线索不是世界变化的根源，而是世界状态变化被玩家看见后的表现层。
```

### 4. plans

放路线图和阶段计划。

建议建立：

```text
chronicle-godot/texts/plans/roadmap.md
chronicle-godot/texts/plans/milestone_0_project_cleanup.md
chronicle-godot/texts/plans/milestone_1_world_sim_mvp.md
```

### 5. archive

放过期但暂不删除的文档。

不要删除旧文档。

## 九、第五阶段：建立 `texts/README.md`

请新增或更新：

```text
chronicle-godot/texts/README.md
```

内容必须包含：

```markdown
# Chronicle 文档索引

## 文档目录分工

- log/：每日开发指令与执行流水，一天一个 md 文件，由用户追加维护。
- texts/reports/：任务完成后的报告。
- texts/specs/：长期系统规格。
- texts/decisions/：架构决策记录 ADR。
- texts/plans/：路线图和阶段计划。
- texts/archive/：过期、损坏或废弃但暂不删除的文档。

## 当前核心方向

Chronicle 是一个自运行世界驱动的文字冒险 RPG。

世界演化层是核心。
事件与线索是表现层。
玩家控制的角色只是世界中的一个参与者，而不是世界唯一驱动源。

## 当前实际运行入口

- 主场景：scenes/ui/mainui.tscn
- 主交互脚本：scenes/ui/story_player.gd
- 当前世界逻辑：scripts/gen/world_generation_v03.gd

## 不要继续扩展的旧内容

- 不要继续扩展旧 world_generation.gd。
- 不要在未清理前继续扩写事件池。
- 不要把当前未接入的数据、素材、文档直接判定为无用。
- 不要清理 素材包/，该目录是备用素材库。

## 当前最值得保留的核心循环

线索变化 -> 目标化行动 -> 多阶段处理 -> 事件结果 -> 后果回流到线索、传闻和局部世界状态。

## 后续重构方向

下一阶段应建立 world_sim_mvp：

- 地区状态
- 势力状态
- 资源流动
- 生态变化
- 传闻生成
- 线索投影
- 玩家行为写回世界
```
