# 2026-06-24.4 指令：Due Resolution Policy Prototype

## 任务性质

本次是 v5.1 世界模拟层的到期项判定策略原型任务。

上一轮已经完成：

```text
obligation / exchange
↓
deadline_key + scope
↓
tick_event include_due_checks
↓
DueTriggerSystem
↓
obligation_due / exchange_due
↓
due_status = due
↓
主 status 仍保持 open
```

并通过：

```text
[V5 OBLIGATION EXCHANGE DUE TRIGGER RESULT] PASS
[V5 TICK EVENT SCHEMA SCOPED RESULT] PASS
[V5 MINI WORLD TICK ADAPTER RESULT] PASS
[V5 CONSEQUENCE TRIGGER SETTLEMENT RESULT] PASS
[V5 DOMAIN PRESSURE DEFERRED FOUNDATION RESULT] PASS
[V5 CANDIDATE EFFECT TEMPLATE BATCH1 RESULT] PASS

[V5 SNAPSHOT TRANSACTION EFFECT TEMPLATE RESULT] PASS

[V5 SIM RUNNER WORLD LOG RESULT] PASS
[V5 RELATIONSHIP TRACE RUMOR NARRATIVE RESULT] PASS
[V5 TRANSACTION STATE MEMORY RESULT] PASS
[V5 RAW RULE PROTOTYPE RESULT] PASS
```

本次目标不是做 NPC 自主履约。
本次目标是建立一个显式的 due resolution policy 层。

也就是：

```text
due obligation / due exchange
↓
DueResolutionPolicy
↓
DueResolutionSystem
↓
TransactionResult
↓
TransactionWorldWriter
↓
Store status update
↓
WorldLog resolution entry
```

第一版只支持显式判定：

```text
obligation:
fulfilled
breached
keep_due

exchange:
settled
failed
keep_due
```

本次不要接 UI。
不要修改 rebuild 原型。
不要实现完整世界 Tick。
不要实现 NPC 自主行动。
不要实现全地图 tick。
不要实现完整日程系统。
不要实现自动判定所有 due 项。
不要实现复杂成功率。
不要实现人格 / 忠诚 / 恐惧驱动的履约判断。
不要实现完整传闻传播。
不要实现 AI 文本。
不要实现湖湾镇完整闭环。
不要实现第七哨站长期项目。
不要把世界实体做成 Godot Node。
不要把世界状态写入 Godot 场景树。

## 0. 设计原则

### 0.1 resolution 不是 autonomous action

本次的 resolution 来自显式策略输入，不来自 NPC 自主判断。

允许：

```gdscript
{
  "resolution_id": "resolve_elai_watch_fulfilled",
  "target_kind": "obligation",
  "target_id": "recruit_elai_watch_duty_for_player",
  "resolution": "fulfilled",
  "reason": "manual_test_policy",
  "source": "test"
}
```

禁止：

```text
系统自动判断伊莱性格
系统自动判断伊莱是否去站岗
系统自动扫描所有 due 项并随机判定
```

---

### 0.2 due_status 与主 status 的关系

上一轮定义：

```text
status = open
due_status = due
```

本轮 resolution 后：

```text
obligation fulfilled:
status = fulfilled
due_status = resolved

obligation breached:
status = breached
due_status = resolved

exchange settled:
status = settled
due_status = resolved

exchange failed:
status = failed
due_status = resolved

keep_due:
status = open
due_status = due
```

`keep_due` 表示已经检查过，但本轮不处理。

---

### 0.3 所有判定仍然走事务链

禁止 DueResolutionSystem 直接改 Store。

禁止：

```gdscript
obligation_store.mark_fulfilled(...)
exchange_store.mark_failed(...)
```

必须走：

```text
DueResolutionSystem
↓
TransactionResult
↓
TransactionWorldWriter
↓
ObligationStore / ExchangeStore
```

```text
resolution_id: String，必填
```

```text

settled
failed

```

非法组合必须校验失败，例如：


# 检查点 4：新增 DueResolutionSystem

## 4.1 新增脚本

新增：

```text
chronicle-godot/scripts/sim/consequence/due_resolution_system.gd
```

职责：

```text
读取 SimSnapshot 中已 due 的 obligation / exchange。
根据 DueResolutionPolicy 生成 TransactionResult。
不直接写 Store。
```

---

## 4.2 最小接口

实现：

```gdscript
resolve_due(snapshot, decision: Dictionary) -> TransactionResult
resolve_many(snapshot, decisions: Array) -> Array
```

---

## 4.3 判定前置条件

`resolve_due` 必须检查：

```text
1. decision 合法。
2. target 存在。
3. target.status == open。
4. target.due_status == due。
5. resolution 与 target_kind 匹配。
```

失败时返回 invalid_contract 或 invalid_resolution 类型的 TransactionResult，不崩溃。

建议 `TransactionResult` 增加：

```text
contract_status = "invalid_resolution"
error_reason = "target_not_due" / "target_not_found" / "invalid_resolution"
```

如果已有 invalid_contract 足够，也可复用，但报告必须写明。

---

## 4.4 模板映射

默认模板：

```text
obligation + fulfilled -> obligation_fulfilled_effect
obligation + breached -> obligation_breached_effect
obligation + keep_due -> due_resolution_keep_due_effect

exchange + settled -> exchange_settled_effect
exchange + failed -> exchange_failed_effect
exchange + keep_due -> due_resolution_keep_due_effect
```

如果 record 中存在：

```text
resolution_templates
```

则可优先使用 record 的模板映射。
第一版可以不实现 record override，但要预留字段或写明未实现。

---

## 4.5 变量绑定

DueResolutionSystem 调用：

```text
EffectTemplateResolver.resolve_template_with_bindings()
```

传入：

```text
actor_id
target_id
location_id
rule_id
obligation_id
exchange_id
target_kind
resolution
resolution_id
resolution_reason
resolved_by
resolved_tick_event_id
tick_event_id
trigger_key
scope_type
scope_id
```

建议：

```text
obligation:
actor_id = owner_id
target_id = target_id

exchange:
actor_id = party_a
target_id = party_b

resolved_by:
decision.resolver_actor_id 或 decision.source 或 "system"
```

---

## 4.6 不直接写 Store

DueResolutionSystem 只返回 TransactionResult。
写回仍由：

```text
TransactionWorldWriter
```

完成。
