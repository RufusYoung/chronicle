## 0. 设计原则

### 0.1 TickEvent 是输入契约，不是世界 Tick 本身

本次只定义：

```text
外部输入了什么 tick_event
这个 tick_event 影响哪个 scope
这个 tick_event 触发了哪些 deferred consequence
哪些 consequence 因为 scope / status / limit 被跳过
```

禁止：

```text
自动推进所有地点
自动扫描全世界
自动结算所有义务
自动让 NPC 行动
自动衰减压力
```

---

### 0.2 scope 必须显式

tick_event 需要说明自己的作用范围。

第一版允许：

```text
scope_type: "location"
scope_type: "institution"
scope_type: "region"
scope_type: "global"
```

配合：

```text
scope_id
```

示例：

```gdscript
{
  "tick_event_id": "tick_after_patrol_seventh_outpost_day1",
  "tick_type": "time_event",
  "trigger_key": "after_patrol",
  "scope_type": "institution",
  "scope_id": "seventh_outpost",
  "day": 1,
  "source": "test",
  "max_triggers": 10,
  "label": "巡逻结束"
}
```

`global` 可以没有 `scope_id`。
非 `global` 必须有 `scope_id`。

---

### 0.3 TickResult 必须可审计

tick 不能只返回 success。

必须能回答：

```text
输入的 trigger_key 是什么？
输入的 scope 是什么？
找到多少 pending consequence？
触发多少？
跳过多少？
为什么跳过？
是否因为 max_triggers 截断？
是否有错误？
```

# 检查点 1：新增 TickEvent 规范化与校验

## 1.1 新增 TickEventSchema

新增：

```text
chronicle-godot/scripts/sim/world_tick/tick_event_schema.gd
```

职责：

```text
规范化和校验 tick_event 输入。
```

最小接口：

```text
normalize(event: Dictionary) -> Dictionary
validate(event: Dictionary) -> Dictionary
```

返回结构建议：

```gdscript
{
  "ok": true,
  "errors": [],
  "warnings": [],
  "event": normalized_event
}
```

---

## 1.2 标准字段

标准 TickEvent 字段：

```text
tick_event_id: String，必填
tick_type: String，必填
trigger_key: String，必填
scope_type: String，必填
scope_id: String，非 global 时必填
day: int，可选
time_key: String，可选
source: String，可选
label: String，可选
max_triggers: int，可选，默认 0，表示不限制
```

允许的 `tick_type` 第一版：

```text
time_event
manual_event
test_event
```

允许的 `scope_type` 第一版：

```text
location
institution
region
global
```

---

## 1.3 校验规则

必须检查：

```text
1. tick_event_id 非空。
2. tick_type 非空，且属于允许值。
3. trigger_key 非空。
4. scope_type 非空，且属于允许值。
5. scope_type != global 时，scope_id 必须非空。
6. max_triggers 如果存在，必须 >= 0。
```

校验失败时不要崩溃，返回：

```text
ok = false
errors = [...]
```

# 检查点 3：WorldTickAdapter 支持 schema 和 scope

## 3.1 修改 WorldTickAdapter

修改：

```text
chronicle-godot/scripts/sim/world_tick/world_tick_adapter.gd
```

`apply_tick_event(context, stores, tick_event)` 新流程：

```text
1. 使用 TickEventSchema.normalize / validate。
2. 校验失败时返回 success=false，error_reason="invalid_tick_event"。
3. 构建 SimSnapshot。
4. 从 tick_event 获取 trigger_key / scope_type / scope_id / max_triggers。
5. 只选择匹配 trigger_key + scope 的 pending deferred consequence。
6. 对每个匹配结果调用 ConsequenceTriggerSystem.trigger_deferred(snapshot, deferred_id)。
7. 用 TransactionWorldWriter 写回。
8. 生成 tick result。
9. 写入 WorldLog tick entry。
```

---

## 3.2 不再直接 trigger_deferred_by_key 全量触发

上一轮可以调用：

```text
ConsequenceTriggerSystem.trigger_deferred_by_key(snapshot, trigger_key)
```

本轮为了支持 scope，WorldTickAdapter 应自己先筛选：

```text
pending consequences by trigger_key + scope
```

再逐个调用：

```text
ConsequenceTriggerSystem.trigger_deferred(snapshot, deferred_id)
```

除非你扩展了 ConsequenceTriggerSystem 的 scoped 方法。

禁止：

```text
不区分 scope，直接触发同 trigger_key 全部 pending consequence。
```

---

## 3.3 max_triggers

如果 tick_event 包含：

```text
max_triggers > 0
```

则最多触发该数量的 consequence。

超过的匹配项不触发，计入：

```text
skipped_due_to_limit_count
```

---

## 3.4 TickResult 结构

返回结构至少包含：

```gdscript
{
  "success": true,
  "tick_event_id": "...",
  "tick_type": "...",
  "trigger_key": "...",
  "scope_type": "...",
  "scope_id": "...",
  "source": "...",
  "matched_count": 0,
  "triggered_count": 0,
  "skipped_count": 0,
  "skipped_due_to_scope_count": 0,
  "skipped_due_to_status_count": 0,
  "skipped_due_to_limit_count": 0,
  "error_reason": "",
  "results": [],
  "world_log_entries": [],
  "store_summary": {}
}
```

说明：

```text
matched_count = 符合 trigger_key + scope + pending 的数量。
triggered_count = 实际触发数量。
skipped_due_to_limit_count = 因 max_triggers 没触发的数量。
skipped_due_to_scope_count / skipped_due_to_status_count 可选，如果实现困难，至少在报告中说明当前未统计。
```

---

## 3.5 WorldLog tick entry

每条 tick entry 增加：

```text
tick_type
scope_type
scope_id
day
time_key
source
matched_count
triggered_count
skipped_count
skipped_due_to_limit_count
error_reason
```
