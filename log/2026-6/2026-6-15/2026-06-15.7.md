# 2026-06-15.7 指令：抽象局部故事模块接口与湖湾镇模块化整理

## 一、任务目标

上一阶段已经完成湖湾镇极端饥饿二级闭合。

当前湖湾镇已经具备：

```text
食物危机因果链
微观行动解析
后续反应
恢复与关系回声
多 seed 历史差异
替代路径闭合
极端饥饿二级闭合
历史质量审计
```

但这些系统目前仍围绕湖湾镇、老陈、陈米、玛婶、刘账房这组具体对象展开。继续直接堆湖湾镇细节，会让系统越来越难迁移。

本任务目标是建立 Chronicle 的第一个可复用局部故事模块接口：

```text
LocalStoryModule
RegionSimProfile
LocalStoryPipeline
HistoryQualityAudit
```

把湖湾镇整理为第一个模块：

```text
lake_town_food_crisis_module
```

本任务不创建第二个地点。

本任务不扩地图。

本任务不接 UI。

本任务只做抽象接口、适配包装、测试和文档，让后续“第二个地点”可以按同一结构实现。

---

## 二、任务边界

本任务只做架构抽象、模块包装、无头测试、报告和文档。

不要接正式 UI。

不要修改当前 Demo 行为。

不要修改 `story_player.gd`。

不要修改 `world_generation_v03.gd`。

不要修改 `mainui.tscn`。

不要新增第二个地点。

不要新增大地图模拟。

不要重写湖湾镇全部逻辑。

不要把湖湾镇现有系统强行拆碎到不可维护。

优先采用“接口 + 包装 + 逐步迁移”方式。

本任务的目标不是让代码最优雅，而是让后续第二个地点有明确模板。

## 五、核心原则

### 1. 先抽接口，不扩内容

本任务不要做：

```text
第二个村庄
第二条粮食链
矮人贸易站
林精边境
新地图 UI
```

只做：

```text
湖湾镇现有逻辑如何被包装成一个 LocalStoryModule
第二个地点未来要实现哪些接口
模块如何初始化、tick、输出事实、输出质量审计
```

### 2. 保持湖湾镇行为稳定

抽象之后，以下结果不能被破坏：

```text
20 seed 可运行 30 天
同 seed 复现性通过
不同 seed 差异性通过
unresolved_extreme_hunger = 0
dangling_major_fact = 0
impossible_shop_state = 0
所有回归测试 PASS
```

如果少量具体日期因封装顺序变化发生变化，必须在报告中说明原因；原则上不应改动现有每日 tick 顺序。

### 3. 模块接口只管结构，不管文学表达

LocalStoryModule 不负责写文学文本。

它只负责：

```text
初始化局部状态
推进局部因果
生成 WorldFact
生成 Trace
生成 Memory
生成 NarratableState
生成 ActionCandidate
执行无头模拟行动
输出 HistorySignature
输出 QualityAudit
```

## 七、LocalStoryModule 接口

新增：

```text
chronicle-godot/scripts/sim/local_story_module.gd
```

建议定义接口约定，而不是复杂继承体系。

接口至少包含：

```gdscript
func get_module_id() -> String

func get_module_version() -> String

func get_region_id() -> String

func get_location_ids() -> Array

func get_required_state_keys() -> Array

func initialize_module_state(state: Variant, profile: Dictionary = {}) -> void

func tick_module(state: Variant) -> Array

func build_narratable_states(state: Variant) -> Array

func build_action_candidates(state: Variant, actor_state: Dictionary, narratable_state_id: String) -> Array

func resolve_action(state: Variant, actor_state: Dictionary, action_id: String, narratable_state_id: String) -> Dictionary

func build_history_signature(state: Variant) -> Dictionary

func audit_quality(state: Variant, signature: Dictionary = {}) -> Dictionary

func describe_module() -> Dictionary
```

注意：

* 当前可以用普通 GDScript 类实现。
* 不要求所有旧系统立即继承。
* 可以用 wrapper 调用现有湖湾镇系统。
* 不要为了形式抽象破坏现有测试。

## 八、RegionSimProfile 结构

新增：

```text
chronicle-godot/scripts/sim/region_sim_profile.gd
```

目标：统一 seed profile / 区域 profile / 局部模块 profile 的概念。

建议结构：

```gdscript
{
    "profile_id": String,
    "seed": int,
    "region_id": String,
    "module_id": String,

    "macro_pressure": Dictionary,
    "resources": Dictionary,
    "social_roles": Dictionary,
    "npc_bias": Dictionary,
    "location_bias": Dictionary,
    "external_pressure": Dictionary,
    "quality_targets": Dictionary
}
```

湖湾镇现有 `lake_town_seed_profile.gd` 不要删除。可以将其输出包装进 `RegionSimProfile`。

新增接口：

```gdscript
func build_region_profile(seed_value: int, module_id: String, region_id: String) -> Dictionary

func wrap_lake_town_seed_profile(seed_profile: Dictionary) -> Dictionary

func describe_region_profile(profile: Dictionary) -> Dictionary
```

要求：

* RegionSimProfile 不直接生成 WorldFact。
* RegionSimProfile 不直接指定 outcome_class。
* RegionSimProfile 只描述初始条件、压力、资源、NPC 偏置、地点偏置。

## 九、LocalStoryPipeline

新增：

```text
chronicle-godot/scripts/sim/local_story_pipeline.gd
```

目标：把一个 LocalStoryModule 的每日推进顺序标准化。

建议接口：

```gdscript
func run_days(state: Variant, module: Variant, days: int, profile: Dictionary = {}) -> Dictionary

func tick_once(state: Variant, module: Variant) -> Dictionary

func run_seed_batch(module: Variant, seeds: Array, days: int) -> Dictionary

func build_batch_summary(results: Array) -> Dictionary
```

`tick_once()` 输出：

```gdscript
{
    "day": int,
    "created_fact_ids": Array,
    "created_trace_ids": Array,
    "created_memory_ids": Array,
    "created_narratable_state_ids": Array,
    "quality_flags": Array
}
```

注意：

* pipeline 不应包含湖湾镇专用逻辑。
* 湖湾镇专用逻辑留在 `lake_town_food_crisis_module.gd` 内部或现有系统中。
* pipeline 只负责调用模块接口。
