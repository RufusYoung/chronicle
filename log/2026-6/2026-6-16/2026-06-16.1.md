# 2026-06-16.1 指令：建立湖湾镇局面卡片与世界表面层

## 一、任务目标

上一阶段已经完成湖湾镇开发者可视化世界面板：

```text
LakeTownWorldViewer
```

它已经能在 Godot 中展示：

```text
20 个 seed
30 天历史时间线
WorldFact
Trace
Memory
NarratableState
NPC 状态
地点状态
QualityAudit
Profile
Raw Signature
```

但当前界面仍偏向数据库观察器和调试控制台。用户能看到事实和 JSON，却还不能直观感受到：

```text
湖湾镇今天是什么样
谁在哪里
谁的处境变了
店铺现在是什么状态
街上有什么痕迹
镇上的人可能听见了什么
今天和前几天的关系是什么
```

本任务目标是建立 Chronicle 的第一个“世界表面层”：

```text
LivingSurface
```

并在现有开发者观察器中增加：

```text
今日局面卡片
人物状态卡
地点状态卡
痕迹摘要
因果来源摘要
```

本任务不是正式玩家 UI。

本任务不接入主 Demo。

本任务不让 UI 生成事实。

本任务只把已有的 WorldFact、Trace、Memory、NarratableState、NPC 状态和地点状态翻译为可观看的局面。

目标是让开发者打开湖湾镇 viewer 后，首先看到的不是 Raw Signature，而是：

```text
湖湾镇 · Day 10

老陈的铺子今天没有正常开门。
门边贴着旧账条，粮价比前几天更高。

陈米坐在门槛旁，袖口沾着灰白色粮粉。
她看见有人靠近时，把旧布袋往身后挪了一下。

可见痕迹：
- 店门半掩
- 袖口粮粉
- 废弃粮仓少了一袋发霉麦子

相关人物：
- 陈米：饥饿高，恐惧上升
- 老陈：压力高，债务高
- 玛婶：尚未介入
```

注意：这不是文学生成。所有内容必须能追溯到结构化状态和事实。

本任务只做开发者可视化增强、LivingSurface 数据层、局面卡片生成、测试和报告。

不要接正式 UI。

不要修改当前 Demo 行为。

不要修改 `story_player.gd`。

不要修改 `world_generation_v03.gd`。

不要修改 `mainui.tscn`。

不要新增第二地点。

不要新增正式玩家输入。

不要做 AI 文本生成。

不要接大模型。

不要把局面卡片写成随机文案。

不要让 UI 决定世界事实。

不要让 UI 修改 `WorldSimState`。

不要让 UI 直接创建 `WorldFact`、`Trace`、`Memory` 或 `NarratableState`。

本任务的核心是：

```text

↓
世界表面层把事实、痕迹、人物和地点翻译为可读局面
```

不是：

```text

↓

```

## 五、核心原则

### 1. 世界表面层只翻译事实，不创造事实

允许：

```text
根据 chen_mi_took_spoiled_grain + spoiled_grain_bag Trace + chen_mi.hunger 高
生成局面句：
“陈米怀里抱着一只旧布袋，袋口露出灰白色麦粒。”
```

禁止：

```text
没有 spoiled_grain_bag Trace，却写“袋口露出麦粒”。
```

允许：

```text
根据 old_chen_shop_forced_abnormal_closure + dark_shop_in_business_hours Trace
生成局面句：
“本该开门的时候，老陈的铺子却暗着。”
```

禁止：

```text
没有关店事实，却写“铺子关了很久”。
```

### 2. 默认展示“今日局面”，JSON 后置

当前 viewer 默认视觉重心是时间线和 JSON。

本任务要把视觉重心改成：

```text
今日局面卡
人物状态卡
地点状态卡
可见痕迹
因果来源
```

Raw JSON 仍保留在底部分页，但不作为主视觉。

### 3. 生动不等于华丽

局面文本要短、清楚、具体。

禁止写成小说段落堆砌。

禁止过度文学化。

禁止 AI 味抒情。

推荐风格：

```text
老陈的铺子今天没有正常开门。
门边的旧账条还在，墨迹比昨天更淡。
陈米坐在门槛旁，手里攥着一只旧布袋。
```

不推荐：

```text
命运的阴影笼罩着湖湾镇，饥饿的寒风穿过人心。
```

### 4. 每张卡都必须有来源

每张局面卡必须包含：

```text
source_fact_ids
trace_ids
memory_ids
narratable_state_ids
state_keys
```

至少 `source_fact_ids` 或 `trace_ids` 不能全空。

## 七、LivingSurfaceCard 数据结构

新增 `LakeTownLivingSurfaceBuilder`。

建议卡片结构：

```gdscript
{
    "card_id": String,
    "seed": int,
    "day": int,
    "title": String,
    "subtitle": String,
    "location_id": String,
    "location_name": String,

    "scene_summary": String,
    "visible_details": Array,
    "people_present": Array,
    "location_state_lines": Array,
    "trace_lines": Array,
    "memory_echo_lines": Array,
    "cause_lines": Array,
    "quality_lines": Array,

    "source_fact_ids": Array,
    "trace_ids": Array,
    "memory_ids": Array,
    "narratable_state_ids": Array,
    "state_keys": Array,

    "tone_tags": Array,
    "severity": String,
    "card_type": String
}
```

字段说明：

* `scene_summary`：2–4 句，描述今日局面。
* `visible_details`：可见细节，不超过 6 条。
* `people_present`：人物状态摘要。
* `location_state_lines`：地点状态摘要。
* `trace_lines`：痕迹摘要。
* `memory_echo_lines`：记忆或关系回声摘要。
* `cause_lines`：为什么会这样，引用事实链。
* `quality_lines`：是否有质量标记或坏结果。
* `severity`：`calm`、`tense`、`critical`、`recovery`、`bad_outcome`。
* `card_type`：`daily_surface`、`crisis`、`recovery`、`closure`、`memory_echo`、`quality_warning`。

## 八、局面卡片生成规则

### 1. 优先使用 NarratableState

如果某一天有 `NarratableState`，优先从 NarratableState 生成主卡。

示例：

```text
chen_mi_hiding_spoiled_grain_scene
collapsed_child_at_shop_step_scene
old_chen_left_shop_to_seek_help_scene
chen_mi_stays_with_ma_shen_scene
```

主卡必须引用：

```text
source_fact_ids
trace_ids
narratable_state_id
```

### 2. 无 NarratableState 时，从关键 WorldFact 生成卡片

如果当天没有 NarratableState，但有关键事实，也生成局面卡。

关键事实包括但不限于：

```text
lake_town_food_price_rising
guard_locked_abandoned_granary
chen_mi_blocked_by_guard_seal
chen_mi_took_spoiled_grain
old_chen_closed_shop_due_to_family_crisis
chen_mi_ate_spoiled_grain
chen_mi_collapsed_from_hunger
old_chen_sold_shop_goods_for_food
old_chen_took_chen_mi_to_seek_help
ma_shen_emergency_food_for_chen_mi
chen_mi_temporarily_stayed_with_ma_shen
creditor_left_debt_notice
```

### 3. 没有新增事实但状态恶化时，生成状态卡

如果当天没有新增关键事实，但状态进入明显区间，可以生成“状态延续卡”。

条件示例：

```text
chen_mi.hunger >= 90
old_chen.stress >= 90
old_chen.debt >= 90
old_chen_shop.is_open == false
```

但必须满足：

```text
前 3 天内存在相关 source_fact
或已有 Trace / Memory 可支撑
```

禁止凭空生成。

### 4. 每天最多展示 1 张主卡 + 2 张附属卡

避免界面变成卡片堆。

优先级：

```text
critical hunger / collapse
major action / theft / closure
recovery / help / relocation
guard / debt / market
background status
```

## 十、世界表面层示例

### 示例 1：陈米取粮

输入事实：

```text
chen_mi_took_spoiled_grain
old_chen_closed_shop_due_to_family_crisis
spoiled_grain_bag Trace
child_hiding_bag Trace
chen_mi hunger 高
old_chen stress 高
```

输出卡：

```text
标题：老陈铺子后门的旧布袋
地点：老陈的铺子

老陈的铺子今天没有正常开门。
陈米坐在后门边，怀里抱着一只旧布袋。
袋口露出灰白色的麦粒，她看见有人靠近时把袋子往身后挪了一下。

可见痕迹：
- 门边贴着涨价后的粮价牌
- 陈米袖口沾着粮粉
- 废弃粮仓少了一袋发霉麦子

人物：
- 陈米：饥饿高，恐惧上升
- 老陈：压力高，债务高
```

### 示例 2：守卫封仓

```text
标题：废弃粮仓的新封条
地点：废弃粮仓

废弃粮仓门上多了一道守卫封条。
门前有几行小脚印，在封条前停住，又折回镇里。

可见痕迹：
- 守卫封条
- 粮仓门前的小脚印
- 被风吹歪的警示牌

人物：
- 陈米：饥饿仍高，恐惧上升
- 守卫：开始注意粮仓附近的孩子
```

### 示例 3：极端饥饿倒下

```text
标题：店门口倒下的孩子
地点：老陈的铺子

陈米倒在老陈铺子的门槛边。
她手边的空碗翻在地上，碗底没有剩下东西。
老陈没有站在柜台后，店门也没有完全打开。

可见痕迹：
- 门槛边的空碗
- 店内少了一些能卖的旧货
- 门板内侧挂着未收起的账条

人物：
- 陈米：饥饿极高，健康下降
- 老陈：压力极高，准备离店求助
```

这些示例只作为模板目标，实际输出必须由当前 state 和事实决定。


```text
没有事实来源就写重要场景。
```


