# 2026-06-16.2 指令：湖湾镇世界观察器版式重排与连续感增强

## 一、任务目标

上一阶段 `16.1` 已经完成湖湾镇 `LivingSurface` 世界表面层，并在开发者 viewer 中增加了：

```text
今日局面卡
人物状态卡
地点状态卡
可见痕迹
因果来源
底部 JSON 调试分页
```

当前界面已经能从 `WorldFact / Trace / Memory / NPC 状态 / 地点状态` 生成可读局面，但从实际查看效果看，仍存在明显问题：

```text
1. 底部 JSON 调试区仍然占据大量主视觉。
2. 今日局面卡被挤在右侧，文字显示空间太窄。
3. 中间时间线仍以 fact_id 为主，开发味过重。
4. 选中某一天后，只显示“今天发生了什么”，缺少“前因 / 今日 / 后果苗头”。
5. 人物和地点卡有了，但还不像一个可观察的湖湾镇。
```

本任务目标是把 `LakeTownWorldViewer` 从“带局面卡的调试器”推进为“开发者世界观察窗”。

重点不是新增世界事实，而是调整呈现：

```text
今日局面卡成为主视觉。
JSON 退到底部调试区。
时间线改成中文历史线，fact_id 退到调试信息。
选中某一天时，主动展示前因、今日、后果苗头。
```

本任务不是正式玩家 UI。

本任务不接入当前 Demo。

本任务不修改 `story_player.gd`。

本任务不修改 `world_generation_v03.gd`。

本任务不修改 `mainui.tscn`。

本任务不让 UI 生成事实。

## 六、主视觉调整要求

### 1. 今日局面卡成为主视觉

当前右侧局面卡太窄，容易被截断。

本任务要求：

```text
今日局面卡移动到中间主区域。
卡片宽度必须明显大于时间线和右侧状态栏。
局面摘要优先显示，不被 JSON 抢占视线。
```

中间主区域至少显示：

```text
地点 / Day
标题
局面摘要
前因
今日
后果苗头
可见痕迹
因果来源
质量标记
```

示例显示：

```text
湖湾镇 · Day 16

刘账房在关着的店门上留下了催债告示。

前因：
- Day 13：陈米倒在店门口。
- Day 14：老陈带陈米离店求助。

今日：
- 刘账房在老陈铺子门口留下新的催债告示。

后果苗头：
- 老陈债务仍处于极高区间。
- 店铺处于异常关闭状态。
- 陈米已经离开铺子，暂时不在这里。

可见痕迹：
- 关着的店门
- 新的催债告示
```

### 2. 底部 JSON 默认弱化

底部 JSON 调试分页保留，但不要占据半屏。

要求：

```text
底部调试区默认高度降低。
可以增加“显示/隐藏调试数据”按钮或 CheckBox。
默认打开时，主视觉仍然是局面卡。
```

如果实现折叠成本过高，至少要调整 VSplitContainer 比例，让上方世界观察区占主要空间。

### 3. 时间线中文优先

当前中间时间线格式类似：

```text
Day 16 | creditor_left_debt_notice | 刘账房留下催债告示
```

调整为：

```text
Day 16｜刘账房留下催债告示
```

fact type 不要和中文摘要平级显示。

可以改为：

```text
Day 16｜刘账房留下催债告示
    creditor_left_debt_notice
```

或者将 fact type 放在底部详情 / tooltip / 调试分页。

要求：

```text
时间线第一眼看中文历史。
fact_id 仍可查，但不抢主视觉。
```

### 4. 增加 Day 1–30 日期导航

左侧或顶部新增日期导航。

要求：

```text
能直接点击 Day 1 到 Day 30。
点击日期后刷新今日局面卡。
即使某天没有新增关键事实，也能显示状态延续卡或“今日无重大新事实”。
```

如果当天没有卡片：

```text
显示：
今日没有新的重大事实。
但人物和地点状态仍可查看。
```

## 七、连续感增强

新增连续性摘要结构。

### ViewModel 新增接口

修改：

```text
scripts/dev/lake_town_world_view_model.gd
```

新增：

```gdscript
func build_continuity_context(run_result: Dictionary, day: int) -> Dictionary

func build_preceding_events(run_result: Dictionary, day: int, limit: int = 3) -> Array

func build_followup_hints(run_result: Dictionary, day: int) -> Array

func build_readable_timeline(run_result: Dictionary) -> Array

func build_day_navigation(run_result: Dictionary) -> Array
```

`build_continuity_context()` 返回：

```gdscript
{
    "day": int,
    "preceding_events": Array,
    "today_events": Array,
    "followup_hints": Array,
    "continuity_summary": String,
    "source_fact_ids": Array,
    "trace_ids": Array,
    "state_keys": Array
}
```

### 前因 preceding_events

选取当前 day 之前最近 1–3 个相关事实。

优先级：

```text
同一人物相关事实
同一地点相关事实
当前卡 source_fact_ids 的 cause_fact_ids
近三日关键事实
```

示例：

```text
Day 13：陈米倒在店门口。
Day 14：老陈带陈米离店求助。
```

### 今日 today_events

显示当前 day 的关键事实中文摘要。

如果有多个事实，最多显示 3 条。

### 后果苗头 followup_hints

根据当前状态生成短句，但必须有状态依据。

示例规则：

```text
old_chen.debt >= 85
=> 老陈债务仍处于极高区间。

old_chen_shop.is_open == false
=> 店铺仍未恢复正常营业。

chen_mi.location_id != old_chen_shop
=> 陈米已经不在老陈铺子。

chen_mi.health <= 70
=> 陈米健康仍在下降。

quality_flags 非空
=> 此 seed 存在质量标记。
```

禁止凭空预测未来事件。

后果苗头只能描述：

```text
当前状态可能带来的紧张感
```

不能写：

```text
明天一定会发生什么
```

## 八、人物状态卡优化

右侧人物状态卡不要再像 JSON。

每个人显示：

```text
姓名
当前位置
核心状态等级
状态标签
最近相关事实
```

等级转换：

```text
0–30：低
31–60：中
61–85：高
86–100：极高
```

示例：

```text
陈米
位置：玛婶临时住所
饥饿：极高（100）
恐惧：高（69）
健康：偏弱（76）
状态：temporarily_staying_with_ma_shen

最近相关：
Day 13：陈米倒在店门口
Day 14：老陈带她离店求助
```

必须至少显示：

```text
old_chen
chen_mi
ma_shen
liu_zhangfang
```

如果字段缺失，显示 `-`，不要报错。
