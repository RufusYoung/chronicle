## 八、线索类型映射规则

### 1. 直接映射

```text
smoke  -> 烟柱
tracks -> 足迹
rumor  -> 传闻
river  -> 河流
```

### 2. 间接映射

```text
apparition -> 传闻
checkpoint -> 足迹
caravan    -> 烟柱
```

解释：

```text
apparition 是异常现象或异象传闻，先映射到“传闻”。
checkpoint 是人为活动留下的可追查痕迹，先映射到“足迹”。
caravan 通常伴随营火、道路活动、商队残迹或烟柱，先映射到“烟柱”。
```

本阶段不要新增 UI 类型。

只适配到 v0.3 现有四类线索。

---

## 九、数值映射规则

### freshness

`LeadCandidate.freshness` 直接映射到 v0.3 的 `freshness`。

如果缺失，默认：

```text
0.8
```

范围限制：

```text
0.0 <= freshness <= 1.0
```

### risk

`LeadCandidate.risk` 直接映射到 v0.3 的 `risk`。

建议内部统一：

```text
0.0 <= risk <= 1.0
```

如果原始 risk > 1，则按 100 制处理：

```gdscript
risk = clamp(raw_risk / 100.0, 0.0, 1.0)
```

### urgency -> stage

映射规则：

```text
urgency < 0.35        -> stage 1
0.35 <= urgency < 0.7 -> stage 2
urgency >= 0.7        -> stage 3
```

如果 urgency 缺失，则根据 freshness 和 risk 推断：

```text
risk 高且 freshness 高 -> stage 2 或 3
否则 stage 1
```

## 十、方向映射规则

如果 `LeadCandidate` 中已有方向字段，则保留。

如果没有方向，根据 `region_id` 推断：

```text
mirror_lake_forest -> 西北
border_town        -> 东南
old_ruins          -> 北方
```

这只是临时表现层映射，不代表真实地图已经完成。

方向字段必须稳定。

同一 seed 下，相同 region 生成相同方向。

## 十一、标题与描述生成规则

不要写长文案。

标题要短，能让玩家知道线索是什么。

示例：

```text
smoke + scarcity_high_and_smuggler_raid
-> 远处商队烟迹

tracks + beast_migration
-> 林中迁徙足迹

rumor + information_market
-> 镇上的低声传闻

apparition + cult_ritual_and_mystic_pressure
-> 关于旧遗迹异象的传闻

checkpoint + wardens_patrol
-> 道旁新设的盘查痕迹

river + herb_depletion
-> 河岸药草被采空的迹象
```

描述可以 1 句，不超过 40 个汉字。

描述必须体现 `world_cause`，不能是无因果泛文本。

---

## 十二、行动提示映射

`LeadCandidate.possible_actions` 转换为 v0.3 可显示的行动提示。

不要使用“稳 / 赌 / 退”。

如果原始 action 是：

```text
investigate
protect
rob
ignore
observe
interrupt
follow
report
hunt
set_trap
warn_travelers
```

映射为中文行动名：

```text
investigate     -> 调查
protect         -> 护送
rob             -> 劫掠
ignore          -> 放任
observe         -> 观察
interrupt       -> 打断
follow          -> 跟随
report          -> 报告
hunt            -> 狩猎
set_trap        -> 设陷
warn_travelers  -> 警告旅人
```

如果遇到未知 action：

```text
记录 warning，但不要崩溃。
映射为“谨慎查看”。
```

## 十三、保留世界因果字段

适配后的线索必须保留：

```text
world_cause
related_fact_id
source_region_id
source_faction_id
origin = "world_sim"
```

这些字段用于后续：

```text
1. 玩家处理线索后的结果回写
2. 调试世界状态为什么产生该线索
3. 验证线索不是随机抽卡
4. 后续接入 resolve_lead()
```

如果任何适配后的线索缺少 `world_cause`，测试必须失败。

如果任何适配后的线索缺少 `related_fact_id`，测试必须失败。

## 十四、测试脚本

新增：

```text
chronicle-godot/tests/world_sim_lead_adapter_test.gd
```

测试内容：

```text
1. 固定 seed 加载 world_seed_mirror_lake.json。
2. 运行 world_sim 30 天。
3. 获取 lead_candidates。
4. 调用 adapt_lead_candidates()。
5. 验证适配后线索数量 > 0。
6. 验证所有线索都有 v0.3 必需字段。
7. 验证所有线索都有 world_cause。
8. 验证所有线索都有 related_fact_id。
9. 验证线索类型只属于：足迹、烟柱、河流、传闻。
10. 验证 freshness 和 risk 范围合法。
11. 验证每条线索至少有一个行动提示。
12. 验证同一 seed 下适配结果可复现。
13. 验证第 3 天测试注入后，适配线索签名与无干预版本不同。
```

测试最终输出：

```text
[WORLD SIM LEAD ADAPTER RESULT] PASS
```

注意：测试脚本中为了 A/B 对照插入的行为，必须称为：

```text
测试注入
模拟干预
A/B 对照行为
```

不得称为：

```text
玩家选择
玩家行为
玩家干预
```

除非行为确实来自真实 UI 输入。
