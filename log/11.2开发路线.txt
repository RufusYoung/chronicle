## 里程碑 M0：基础骨架最小化贯通（不做新玩法，只把“通路”打通）

**目的**：让“世界有脉搏”，事件能读到“世界状态”，并且**写回**世界。

### 你要做的事

1. **Autoload 单例检查**

   * `Project > Project Settings > AutoLoad`

     * `_WorldState.gd`（已存在就别动）：保证暴露这些字段（值先可空/0）：

       * `time = { "year":86, "day":1, "hour":8 }`
       * `meters = {}`  // 地区态势表（见下）
       * `facts  = {}`  // 世界事实/计数
       * `chronicles = []` // 世界纪事（后来酒馆对话用）
       * `inventory = {}` // 简易背包（空）
     * `_RNG.gd`（你已有 `_RNG`）：暴露 `randf(), randi_range(a,b)` 即可。

2. **在 WorldState 里开“分区态势表”**（最小集合）

   * 结构：`region_meters = { "<region_id>": { "predator_threat":0, "panic_index":0, "supply_pressure":0, "mystic_flux":0 } }`
   * 现在只对两地创建：`镜湖森林带`、`沉默森林`

3. **在 Region JSON 里放“初始态势”**（不大改，只加轻量键）

   * 顶层（示例）：

     ```json
     "meters_init": { "predator_threat": 1, "panic_index": 0, "supply_pressure": 1, "mystic_flux": 0 }
     ```
   * `WorldGeneration.load_region()` 读到后，写入 `ws.region_meters[meta.id]`（若不存在才初始化）

4. **时间在 `produce_snapshot()` 里最小推进**（你已做：`tick_hours(1)`）

5. **事件“读表改权重”的钩子**

   * 不改事件写法；在 `EventGenerator` 里加一处统一的“权重修正”入口：读 `ws.region_meters[current_region_id]`、`ws.facts`，对候选事件的权重乘系数（例如 `predator_threat > 2` → `encounter:wolf*` ×1.5）

### 验收（手工测试）

* 运行后，继续点击可看到天气/子地点/事件；
* 在一个“会提高 predator_threat 的事件”（例如“追踪狼群”）后，再次生成事件时，狼相关事件明显**更容易**出现；
* **不报错**，`story_player` 的选项和继续键逻辑保持正常。

## 里程碑 M1：角色与背包的可见最小化

**目的**：角色不是幽灵；每个选择**能改到**“我是谁/我有啥”。

### 你要做的事

1. **角色最小三属性 + 两个状态**

   * 放在 `WorldState`（简单就好）：

     * `attrs = { "body":5, "mind":5, "sense":5 }`
     * `status = { "fatigue":0, "sanity":10 }`
2. **背包**

   * `inventory = { "dried_meat":2, "herb":1 }`（起步给一点）
3. **在两地 JSON 的 6–8 个事件里加**非常小的增减：

   * 采集草药 → `inventory.herb += 1`、`mystic_flux += 1`
   * 连续奔波 → `status.fatigue += 2`
   * 夜间惊魂 → `status.sanity -= 1`
   * 喂食/施救 → `attrs.mind += 1`（有冷却/上限）
4. **UI 不做新面板**，先把关键变化**插入文本**（例如“（物资-1）”“（理智-1）”）

### 验收

* 某些选项会**明确改变** fatigue/sanity/背包；
* 下一次生成能读到这些状态（例如疲惫高 → 出现“休整/扎营”可供性，或旅行事件耗时文本更长）。

## 里程碑 M2：NPC 与“酒馆对话”最小化（不做树状对话，先有“世界在说话”）

**目的**：你走进酒馆能听到**当下世界**在议论什么，而不是抽签台词。

### 你要做的事

1. **WorldState 里开“纪事”**（你已预留 `chronicles`）

   * 任何“有后果”的事件/进程，调用 `ws.chronicles.append("Y86-D117：…… #镜湖森林带")`
2. **镜湖森林带新建子地点：雾语酒馆**（JSON 已有子地点体系的话直接加）

   * 事件：`tavern:gossip`
   * 生成文本时：

     * 先从 `ws.chronicles` 抽 1–2 条**最新**（而非纯随机），加工成“有人在聊”的句子（模板化加工即可，“听说昨晚…”，“有个猎人说…”）；
     * 再拼一条本地化情绪语句（读 `panic_index`/`supply_pressure` → 语气紧张/抱怨/祈祷）
3. **NPC 最小影子**

   * 不造完整 NPC 系统；临时造“发言人”名字（姓名表里抽），但把“**发言内容绑定纪事**”——你离开再来，纪事还在，酒馆仍然“记得它”。
   * 可把“最近 5 条纪事”写入 `ws.meta.tavern_feed`，供模板引用。

### 验收

* 连续两次进酒馆，对话会**延续**（因为读的是 `chronicles`），不是每次换一套无关话；
* 当你在别处触发改变 meters/facts 的事件，再回酒馆，能“听到后续”。

## 里程碑 M3：两条“命运线”的最小闭环（跨两地，保证因果）

**目的**：不是任务清单，而是**会自己推进**、写回“地区态势/事实”的世界进程；你可介入，也可以让它自然走向某个结局。

### 命运线 A：**林缘掠食者（Predator in Woods）**（镜湖森林带主，延伸到沉默森林）

* **阶段**：`rumor → trace → stalk → confront → aftermath`
* **推进方式**：

  * `rumor`：夜里在林缘/酒馆，生成纪事“空心嚎叫”；`predator_threat += 1`
  * `trace`：白天出现“新鲜爪痕/残肉”事件；选【追迹】→ `facts["wolf.tracks"]++`
  * `stalk`（需要 tracks≥2 或 `panic_index ≥2`）：出现“夜行灯影”事件；选【设陷】→ 进入对抗
  * `confront`：结局分支：驱赶/重伤/死亡；写回：

    * 成功驱赶：`predator_threat -= 2`、酒馆纪事更新、“守夜人”子地点刷新 3 天
    * 失败：`panic_index += 2`、某摊贩消失 5 天、商队改道（下批事件权重变化）
  * `aftermath`：把结局写入 `chronicles`，线结束或休眠 10 天再复燃

### 命运线 B：**失踪的隐修士（Lost Monk of Silence）**（沉默森林主，回环镜湖）

* **阶段**：`whisper → clue → rite → cross → aftermath`
* **推进**：

  * `whisper`：大雾天/梦境触发呢喃；`mystic_flux += 1`
  * `clue`：在“风切空地/树疤祭桌”找到符片；`facts["monk.clue"]++`
  * `rite`（需要 clue≥2，夜间/新月）：解锁【模仿仪式】与【退后观察】
  * `cross`：仪式成功 → 在镜湖边出现“灰衣僧影”；失败 → 理智-2，`mystic_flux += 1`
  * `aftermath`：成功将僧影引至雾语酒馆→ 新纪事、新对话模板、生意短涨；失败→ 酒馆“闭门祷告”1 天（子地点状态变化）

> 两条线都只**写回 meters/facts/chronicles/子地点状态**；事件本身仍由你的生成器/模板按“当前事实”取材。

### 你要做的事

* 在 `WorldState` 里放 `threads[]`（命运线实例），每回合 `produce_snapshot()` 前后跑一个超轻量 `advance_threads()`：

  * 看看时间、地点、facts 是否满足下个阶段；
  * 每推进一步就**写回**上面那四类信息；
  * 阶段文本不写死，交给事件模板读取“当前阶段 + 绑定对象（狼群/僧影）”去说人话。
* 在两地 JSON 里给 8–12 个事件加**条件钩子**：例如“只有在 `stage == trace` 并且在林缘/小径才会出‘爪痕’类事件”；“`rite` 阶段的新月夜才出‘仪式’选项”。

### 验收

* 你**不管它**也会从 rumor→…→aftermath（以纪事和态势变化体现）；
* 你介入后，能改变“下一回合/隔天”的酒馆对话与地区权重；
* 来回两地，能看到同一条线的**跨区后续**（纪事与 meters 连续）。

# 为什么这么拆 & 你的担心我来回应

* **不会变成“随机池子”**：关键在 M0/M3，“事件是读事实/写事实”，而非“从袋子里摸”。命运线是**进程**，不是任务树。
* **文学性**：我们用“文风包 + 承接器（上一轮 turn_ctx 与 chronicles）”保证语言连贯；主线张力来自**几条命运线交错**，而不是一条硬脚本。
* **可扩展**：你只维护少数“通用规则 + 文风包 + 命运线模板”，数据越多，组合越丰富，但维护成本不暴涨。
* **先两张地图**：把完整回路（Meters→事件→写回→酒馆对话→再影响事件）跑顺了，再扩区就只是“填数据”。
